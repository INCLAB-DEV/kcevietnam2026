### 목적

비즈매칭 신청기간(8/26~9/11) 동안 참가사/바이어의 정보를 최대한 수집하여 AI 매칭 정확도를 높인다.

**참고**: ADR-0001 (Organization 통합), 회의록 (docs/notes/meeting-notes-20260519.md §4 데이터 수집 전략), docs/prototypes/prototype-biz-matching.html

### 가설

| ID | 가설 | 검증 계층 |
|----|------|----------|
| **H1 수집** | 스텝 인디케이터 + 매 단계 입력 이유 설명으로 바이어/참가사 모두 높은 프로필 완성율을 달성할 수 있다 | 선행지표 |
| **H2 품질** | 참가사에게 auto-fill(엑셀/크롤링 기반 사전 입력)을 제공하면, 수동 입력 대비 데이터 품질(키워드 정합도, 필드 밀도, 표현 표준화)이 높아진다 | 중간지표 |
| **H3 성과** | 프로필 데이터 품질이 높을수록(필드 입력율 + 키워드 정합도) AI 매칭 적합도 점수와 미팅 성사율이 올라간다 | 후행지표 |

### 관리지표 (3계층)

**선행 — 입력 행동 (H1 검증)**

| 지표 | 설명 |
|------|------|
| 프로필 완성율 | 바이어 / 참가사 각각. 단계 기반 (바이어 3단계 · 참가사 5단계 중 몇 단계 완료) |
| 신청 전환율 | 링크 클릭 → 1단계 진입 → 프로필 완성. 퍼널 전환율 |
| 평균 완성 시간 | 바이어 / 참가사 각각. 1단계 진입 → 마지막 단계(바이어 3 · 참가사 5) 완료까지 소요 시간 |
| 단계별 이탈율 | 어느 단계에서 이탈하는지. 바이어/참가사 분리 |

**중간 — 데이터 품질 (H2 검증)**

| 지표 | 설명 |
|------|------|
| 필드별 입력율 | 각 필드를 실제 채운 비율. 필수/선택 구분. 바이어/참가사 비교 |
| 키워드 정합도 | 입력 키워드 중 사전 정의 키워드에 매칭되는 비율. auto-fill vs 수동 비교 |
| AI 키워드 채택율 | AI가 추출 제안한 키워드를 사용자가 수락한 비율 |
| auto-fill 채택율 | 참가사가 auto-fill을 수정 없이 수락 / 부분 수정 / 전체 재작성한 비율 |
| 필드 밀도 | 텍스트 필드 평균 글자 수, 키워드 수. auto-fill vs 수동 비교 |

**후행 — 매칭 성과 (H3 검증)**

| 지표 | 설명 |
|------|------|
| 필드별 매칭 기여도 | 어떤 필드가 채워진 프로필이 높은 매칭 적합도를 받는지. 필드 유무별 매칭 점수 분포 |
| auto-fill → 매칭 정확도 | auto-fill 프로필 vs 수동 입력 프로필의 평균 매칭 적합도 점수 비교 |
| 프로필 품질 → 미팅 전환 | 프로필 완성도/품질 등급별 미팅 신청 전환율, 수락율 |

### 공통 설계 원칙

- **1 Action 1 Page**: 한 화면에서 하나의 작업만 수행
- **스텝 인디케이터**: 상단에 단계 인디케이터(바이어 3단계 · 참가사 5단계) + 그래프 채움 인터랙션 (% 바 없음)
- **입력 이유 설명**: 모든 필드의 플레이스홀더에 "이 정보가 매칭에 어떻게 도움이 되는지" 설명
- **단계별 자동저장**: 단계 완료 시마다 서버 저장. 이탈 후 재진입 시 이어서 작성
- **재진입 정책**: 미완성 → 마지막 완료 단계 다음부터 이어서 / 완성 후 → /profile 또는 /exhibitor/profile(내 프로필)로 리다이렉트
- **수정 동선**: 내 프로필에서 "수정" 클릭 → /apply?step=N&from=profile (또는 /exhibitor/apply?step=N&from=profile). 단계 단위 편집. 저장 후 다음 단계로 넘기지 않고 /profile로 복귀
- **Organization당 1개 프로필**: 같은 Organization의 다른 Member가 진입하면 기존 프로필 보이고 수정 가능
- **라우트 분리**: 바이어 `/apply` → `/profile` / 참가사 `/exhibitor/apply` → `/exhibitor/profile`. 역할별 네임스페이스 분리
- **내 프로필 = 네비게이션 허브**: 프로필 완성도 + 매칭 건수(숫자) + 미팅 바로가기 링크. 데이터 복제 아닌 바로가기 역할
- **기간 정책**: 8/26 전 → 카운트다운 안내 / 8/26~9/11 → 정상 운영 / 9/11 후 → 완전 readonly (수정 버튼 숨김, /apply 직접 접근 시 /profile로 리다이렉트)
- **프리필 정보 (기본정보)**: readonly, 수정 불가. 확인 용도

### 단계별 행동 — 바이어 (BM-001)

> ⚠ **3단계로 단순화됨(2026-06-29).** 잠정 5단계(담당자 복수 · 상세니즈 · 예산/도입시기 · 참가정보/추천)는 실제 DX Korea 바이어 등록폼 기준으로 재구성되며 폐기됐다. **단계 구성·필드의 진실원천은 `docs/prd/F-BM-001.md`("폼 구성") + 컬럼 단위는 `docs/db/bm-profile-fields.md`(§1~§7)** 이고, 아래 표는 그 요약이다.

| 단계 | Action | 필드 | 시스템 반응 |
|------|--------|------|------------|
| 1 | 기본정보 확인·보완 | 신청자: 이름(국/영)·직위(국/영)·이메일·전화번호·언어·통역 필요 여부 / 소속: 소속(국/영)·국가·구분(참가자 구분 8종)·연매출(USD)·직원수. 필수 = 이름(영문)·소속(영문)·이메일·전화번호·국가 | 명단(Registrant) 기반 프리필. "정보가 맞는지 확인해주세요" |
| 2 | 관심분야·소개 | 주요 관심분야(방산 **13분야 고정** 리스트), 기업소개(국/영, 500자·필수=영문), 지출 가능 예산(USD, 선택), 도입 시기(선택) | 관심분야는 시드 키워드 조인(자유입력 아님). 텍스트 필드를 채우면 하단에 AI 키워드 추가 제안 영역 노출 — 사전 정의 키워드에 부합하는 것만 제안, 추가 여부는 사용자 선택 |
| 3 | 확인·제출 | 최종 요약 확인 | 폼 자체는 **저장만** 하고(`저장하고 나가기` → `/welcome`), **제출(`submitted`) 트리거는 `/welcome`의 액션**이다(FE ADR-0002 §4). 제출 후 "운영 검토(승인) 대기" 안내 |

**넛지 전략 (바이어)**: 자기이익 기반. 매 필드 플레이스홀더에 입력 이유 설명. 예: "현재 사용 중인 장비를 알려주시면, 업그레이드에 적합한 기업을 우선 매칭해드려요"

### 단계별 행동 — 참가사 (BM-002)

| 단계 | Action | 필드 | 시스템 반응 |
|------|--------|------|------------|
| 1 | 기본정보 확인 | 회사명, 부스번호, 담당자 (readonly) | 엑셀 기반 프리필. "정보가 맞는지 확인해주세요" |
| 2 | 전시 품목 | 전시할 제품/서비스 설명 (텍스트) | 핵심 필드. "전시 품목을 상세히 적을수록 관심 있는 바이어와 정확히 매칭됩니다" |
| 3 | 회사 소개 + 강점 | 회사 설명 (텍스트), 차별점/강점 (텍스트) | 텍스트 필드 채우면 하단에 AI 키워드 추가 제안 영역 노출 (바이어와 동일 패턴) |
| 4 | 타겟 바이어 | 만나고 싶은 바이어 유형/조건 (텍스트) | 매칭 엔진 활용. "원하는 바이어 유형을 적으면 AI가 우선 매칭합니다" |
| 5 | 완료 | 최종 확인 + 제출 | "비즈매칭 신청기간 종료 후 매칭 결과를 알려드릴게요" |

**넛지 전략 (참가사)**: 경쟁심리 기반. "프로필을 채울수록 바이어 매칭률이 올라갑니다"

### 핵심 포인트

- 개인화 링크 = 인증 완료. 별도 로그인/역할 선택/기업 인증 불필요
- **바이어 3단계 · 참가사 5단계**(단계 수는 서로 다르다), 1 Action 1 Page 원칙
- 스텝 인디케이터 + 상단 그래프 채움 인터랙션으로 진행률 표시 (% 바 없음)
- 텍스트 입력 시 AI 키워드 추가 제안이 인라인 노출 (별도 단계 아님) — 바이어는 2단계(관심분야·소개), 참가사는 3단계(회사소개+강점)
- AI 제안 키워드는 사전 정의 키워드 체계에 부합해야 함, 추가 여부는 사용자 선택
- 매칭 결과는 신청기간 종료 후 -- 즉시 나오지 않음
- Organization당 1개 프로필. 다른 Member 진입 시 기존 프로필 조회/수정 가능
- 바이어 하위 유형(자발적/초청)은 데이터로 구분, 사용자 경험은 동일
- 키워드 카테고리 체계 및 매칭 로직은 CTO 협의 필요 (CONTEXT.md flagged)

### 핵심 포인트

- **기업 탐색 = 단일 허브**: AI 추천(구 BM-003) + 전체 기업(구 CL-001) + 관심기업을 하나의 페이지에 통합
- **AI 추천이 기본 탭**: NABI의 차별점. 진입 시 AI 추천부터 보여줌
- 핵심 역할은 **발견(discovery)** — 수락/거절은 내 미팅(MY-001/002) 페이지의 역할
- 매칭 카드 후보 필드 (바이어→참가사 카드): 회사명, 전시품목 키워드, 부스 위치, 강점, 적합도 %, 추천 이유
- 매칭 카드 후보 필드 (참가사→바이어 카드): 바이어 소속(기관명), 관심 분야 키워드, 예산 범위, 도입 시기, 적합도 %, 추천 이유. 개인명/직급은 미팅 수락 후 공개
- 카드 최종 노출 필드는 프로토타입에서 인지 부하 테스트 후 확정 (정보 과다 → 인지 안 됨 리스크)
- 매칭 제안 타이밍: 비즈매칭 신청 마감(9/11) 후 일괄 생성·발송. 전체 데이터 기반 최적 매칭
- 이메일 분리: ① 매칭 완료 안내 ("N개 기업이 매칭되었습니다") ② 미팅 신청 알림 (상대방이 미팅 신청). 두 이메일 모두 → 내 미팅(MY-001)으로 딥링크
- **내 미팅 → 기업 탐색 동선**: 내 미팅에서 "기업 탐색" 버튼 제공 → /discover AI 추천 탭으로 이동. 내 미팅이 중앙 허브
- 카드 수량: 적합도 기준 이상 전부 제공. 적합도 높은 순서대로 정렬
- **스와이프 UI** (AI 추천 탭): 한 번에 한 장씩 카드 표시 (데이팅 앱 패턴). 발견 집중 + 인지 부하 최소화
- **스와이프 완료 화면**: "모든 AI 추천을 확인했습니다! 관심기업 N개 / 미팅 신청 N건" 요약 + "전체 기업에서 더 찾아보기" 버튼 → 전체 기업 탭 전환 유도
- 카드 액션 4가지: ① 미팅 신청 ② 관심기업 등록 ③ 관심없음 ④ 상세보기. 스와이프 제스처↔액션 매핑은 프로토타입에서 테스트 후 확정
- **기업 상세(DV-002)**: /discover/:organizationId. 프로필 상세 + AI 추천 이유 + 미팅 신청 CTA. 정보량이 많아 바텀시트로는 부족. 1차(데모)에서는 추천 이유를 카드와 동일하게 표시, AI 협업 제안은 이후 구체화
- 바이어/참가사 완전 대칭 — 양쪽 모두 동일한 탐색 경험
- Visitor는 전체 기업 탭만 이용 가능. BM-001 완료(On-site Buyer 전환) 후 AI 추천 탭 + 미팅 신청 활성화
- **첫 진입**: 온보딩 스크린 2~3장 (브랜드 각인 + 기능 소개) → 내 미팅. 재방문 시 스킵
- **랜딩 페이지**: 전원(바이어/참가사/Visitor) 내 미팅(MY-001)이 랜딩. 내 미팅에서 "기업 탐색" 버튼으로 /discover 이동
- **기간 정책**: 매칭 전(~9/11) → "현재 비즈매칭 신청을 받고 있습니다. 메일을 확인해주세요" 안내. 전체 기업 탭은 활성(사전 탐색 가능). 매칭 후(9/12~) → 전체 기능 활성
- 전체 기업 탭: 상대 역할만 표시 (바이어 → 참가사 목록, 참가사 → 바이어 목록). DX Korea 범위 결정
- 카드 모드에서는 채팅(NABI) 동선 없음 — ADR-0003 (상호 배타)
- 상세보기에서 방산 전문용어 설명 자연스럽게 노출
- 매칭 근거 투명: 적합도 % + 추천 이유 + 키워드 매칭
- 모든 결과는 Schedule Table에 기록

### 핵심 포인트

- 바이어 / 참가사 — 완전히 동일한 플로우. Visitor는 BM-001 완료(On-site Buyer 전환) 후 동일

- 같은 상대에게 동시 활성 미팅은 1건만. completed 후 추가 가능
- 취소 시 경고 넛지: "추천 우선순위 하락 가능". 1차에서는 문구만, 알고리즘 반영 이후
- 알림: 이메일 7종 (신청/수락/거절/역제안/취소/리마인더/리뷰요청). 수락/거절 행위는 MY-001 웹에서
- Forced Matching: Organizer 배정 → accepted 직접 삽입, 거절 불가
