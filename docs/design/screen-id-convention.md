# 화면(뷰) ID 체계 — Screen/View ID Convention

NABI 상세설계서·페이지 관리의 화면 ID 규칙. **단일 레지스트리 = `docs/page-list.csv`** (모든 화면·하위화면이 여기 한 행). 관리·조회·부여·감사는 `/view-id` 스킬이 이 규칙을 따라 수행한다.

## ID 문법

| 종류 | 규칙 | 예 |
|---|---|---|
| **페이지** | `{도메인2자}-{3자리}` | `AU-001`, `OP-002` |
| **팝업/모달/시트/다이얼로그/바텀시트** | `{부모ID}-P{n}` | `AU-001-P1`, `OP-002-P4` |
| **플로우 단계/상태(스텝)** | `{부모ID}-S{n}` | `AU-001-S1` |

- `P` = Popup류(팝업·모달·시트·바텀시트·다이얼로그) — 부모 화면 위에 뜨는 오버레이.
- `S` = Step/State — 팝업이 아닌 **화면 단계/상태**(예: 로그인 플로우의 약관 동의 단계). 전이형 스피너·인라인 에러 등 사소한 상태는 보통 ID 생략.
- `n` = 부모별 1부터. 기존 최대 번호 + 1.

## 유형(page-list `유형` 컬럼) 어휘

`페이지` · `모달` · `팝업` · `시트` · `바텀시트` · `다이얼로그` · `단계` · `컴포넌트`

(모달/시트/다이얼로그/바텀시트/팝업 = 모두 `-P` 계열. `단계` = `-S` 계열. `컴포넌트`=NV-001 같은 전역 크롬.)

## 도메인 코드 (페이지 ID 접두 2자)

| 코드 | 도메인 |
|---|---|
| AU | 인증(로그인) |
| HM | 홈·입장 전 랜딩 |
| DV | 기업 탐색·상세 |
| MT | 미팅 신청 |
| MY | 내 미팅·리뷰 |
| BM | 프로필·비즈매칭 신청 |
| OP | 운영사 |
| NT | 알림 |
| NV | 공통 네비/크롬(컴포넌트) |

## 라우트 컬럼 규칙

- **페이지** = 실제 경로(`/login`, `/organizer/members`, `/discover/:organizationId`).
- **하위 화면(-P/-S)** = `"{부모ID} 내"` (팝업·단계는 독립 URL 없음). 조건 있으면 괄호로(예: `MY-001 내(좁은 폭)`).

## page-list.csv 컬럼(11)

`Page ID,기능 ID,사용자,페이지명,라우트,유형,접근,주요기능,프로토타입,개정이력,오픈일`

- `기능 ID` = 부모와 동일(하위 화면은 부모 기능에 속함).
- `주요기능`엔 소스 컴포넌트명을 함께 적는다(예: `login-flow ConsentDocSheet`, `review-flow TranscriptSheet`).
- 하위 화면 추가 시 `개정이력`=추가일, `프로토타입`·`오픈일`=빈칸. 콤마 포함 필드는 큰따옴표.
- **배치**: 부모 페이지 행 바로 아래에 `-S` → `-P` 순으로.

## 예시 (AU-001 계열)

```
AU-001      통합 로그인    /login       페이지
AU-001-S1   약관 동의      AU-001 내    단계      ('전문 보기' → AU-001-P1)
AU-001-P1   약관 상세      AU-001 내    시트
```

## 감사 대상(코드 → 화면 매핑)

- **페이지**: `frontend/app/**/page.tsx` → 라우트.
- **팝업류(-P)**: `frontend/components/**`의 `<Dialog>`/`<Sheet>`/`<AlertDialog>`/`<Drawer>` (`ui/`·`.test.` 제외). Title로 이름 추출.
- **단계/상태(-S)**: 플로우 상태머신(예: `login-flow`의 phase 유니온) 중 화면급 상태.

빠진 화면(코드엔 있는데 page-list 없음)·고아 ID(page-list엔 있는데 코드 없음)를 리포트한다.
