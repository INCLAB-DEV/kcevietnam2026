# F-BM-004: 내 프로필 (바이어)

> 바이어가 BM-001에서 작성한 **자기 프로필을 다시 보고, 항목별로 고치는** 페이지. 작성(F-BM-001)의 사후 짝 — 작성이 "한 번 채워 매칭에 들어가는 입구"라면, 이 페이지는 "이미 낸 정보를 확인하고 최신으로 유지하는 출구"다. 현황 허브 역할은 갖지 않는다(HM-001 담당).

|------|------|
| Page ID / 기능 ID | BM-004 / F-BM-004 |
| 라우트 / 형태 | `/profile` / 페이지 |

| 관리지표 | 프로필 수정 빈도, 프로필 완성도, 항목별 수정 진입 후 완료율 |

| 관련 PRD | F-BM-001(바이어 프로필 작성 — 수정 진입 대상), F-HM-001(홈 대시보드 — 현황 허브) |

> ⚠ **현황 허브 역할은 HM-001(홈 대시보드)로 이관** (2026-06-14). 이 페이지는 프로필 조회/수정 전용 — 미팅·매칭 현황 및 바로가기는 두지 않는다(중복 제거).

---

## Problem Statement

바이어 입장에서:

- BM-001 5단계로 내 니즈(관심분야·상세니즈·예산/도입시기 등)를 한 번 냈는데, **내가 무엇을 어떻게 적었는지 나중에 다시 볼 곳이 없다.** 매칭이 들어와도 "내가 어떤 조건으로 신청했더라"를 확인하지 못하면 불안하다.
- 조직 사정이 바뀌어(예산·도입 시기·관심 분야가 달라져) **일부만 고치고 싶은데**, 처음부터 5단계를 다시 거치게 만들면 안 된다. 한 항목 고치자고 전체를 다시 쓰는 건 부담이다.
- 내 프로필이 **충분히 채워졌는지(완성도)** 한눈에 모르겠다. 비어 있는 항목이 매칭 품질을 떨어뜨리는지 알 길이 없다.
- 나는 초청 바이어인지 일반 바이어인지에 따라 **매칭을 받을 때 동작이 달라지는데**(즉시 확정 vs 수락 필요), 정작 내가 어느 유형인지 화면에서 확인할 수 없다.

## Solution

바이어 입장에서:

- BM-001에서 작성한 **전체 정보를 한 페이지에서 그대로 조회**한다(기본정보·관심분야·상세니즈·예산/도입시기). 내가 낸 조건을 언제든 다시 본다.
- 각 섹션의 "수정"을 누르면 **그 항목에 해당하는 단계만** 작성 폼으로 바로 열린다(`/apply?step=N&from=profile` 딥링크). 한 단계만 고치고 프로필로 돌아온다 — 전체 재작성 없음.
- **내 바이어 유형**(초청 바이어 / 일반 바이어)을 표시해, 매칭 수신 시 수락 규칙이 어떻게 다른지 본인이 인지한다(ADR-0005).
- 프로필 **완성도**를 확인해 어디가 비었는지 알고 채울 수 있다(계산 규칙은 HM-001과 공유).
- 이미 매칭에 들어간 상태(승인 완료=`approved`)에서 수정해도, 저장은 **작성과 동일한 원자적 경로**를 타므로(ADR-0009) 반쪽 저장으로 매칭이 오염되지 않는다.

## User Stories

1. As a 바이어, I want BM-001에서 작성한 내 프로필 전체를 한 페이지에서 보기를, so that 내가 어떤 조건으로 비즈매칭에 신청했는지 언제든 확인한다.
2. As a 바이어, I want 기본정보·관심분야·상세니즈·예산/도입시기가 섹션별로 정리되어 보이기를, so that 어디에 무엇을 적었는지 빠르게 파악한다.
3. As a 바이어, I want 각 섹션마다 "수정" 진입점이 있기를, so that 고치고 싶은 항목으로 바로 들어간다.
4. As a 바이어, I want 수정 시 그 항목에 해당하는 단계만 작성 폼으로 열리기를(`/apply?step=N&from=profile`), so that 전체 5단계를 다시 거치지 않고 한 단계만 고친다.
5. As a 바이어, I want 수정 후 다시 내 프로필 화면으로 돌아오기를, so that 어디서 수정을 시작했는지 잃지 않고 결과를 바로 확인한다.
6. As a 바이어, I want 내 바이어 유형(초청/일반)이 표시되기를, so that 매칭 수신 시 내 건이 즉시 확정인지 수락이 필요한지 미리 안다(ADR-0005).
7. As a 바이어, I want 내 프로필 완성도를 확인하기를, so that 비어 있는 항목을 알고 채워 매칭 품질을 높인다.
8. As a 바이어, I want 아직 비어 있는(미작성) 항목이 시각적으로 구분되기를, so that 어디를 보완해야 할지 한눈에 안다.
9. As a 바이어, I want 수정한 내용이 저장되면 그 값이 바로 조회 화면에 반영되기를, so that 변경이 실제로 적용됐음을 확신한다.
10. As a 바이어, I want 내가 이미 매칭 대상(참가자)인 상태에서 항목을 수정해도 매칭 자격이 유지되기를, so that 수정한다고 매칭에서 빠지지 않는다.
11. As a 바이어, I want 내 프로필만 보고 다른 바이어의 프로필은 볼 수 없기를, so that 내 민감한 도입 니즈가 타인에게 노출되지 않는다.
12. As a 바이어, I want 이 페이지를 모바일에서도 편히 보고 고치기를, so that 현장에서 휴대폰으로 프로필을 손본다.
13. As a 바이어, I want 글로벌 네비게이션의 "내 프로필" 메뉴와 홈 대시보드의 프로필 요약 양쪽에서 이 페이지로 들어오기를, so that 어디서든 내 프로필에 닿는다.
14. As a 바이어, I want 이 페이지가 미팅·매칭 현황으로 어수선하지 않고 프로필에만 집중되기를, so that 조회·수정 목적이 흐려지지 않는다(현황은 HM-001).
15. As a 현장(On-site) 바이어, I want 사전등록·초청 바이어와 동일한 내 프로필 화면을 쓰기를, so that 바이어 유형(subtype)에 따라 조회·수정이 제한되지 않는다.

## Implementation Decisions

**진입 경로**

| 진입점 | 트리거 |
|--------|--------|
| 글로벌 네비게이션 "내 프로필" | 메뉴 클릭 |
| HM-001 "내 프로필 요약" | "프로필 수정" 클릭 |

**화면 구조**

- **프로필 전체 조회** — BM-001 5단계에서 작성한 전체 정보를 섹션으로 표시: 기본정보 · 관심분야 · 상세니즈 · 예산/도입시기. (필드는 `buyer_profiles` + `buyer_interest_keywords`, 기본정보는 `organizations`/`members`에서 읽음.)
- **내 바이어 유형 표시** — 초청 바이어(Hosted) / 일반 바이어(사전등록·현장). 매칭 수신 시 수락 규칙이 갈리는 축(ADR-0005). `organization_event_roles.buyer_subtype` 기준.
- **항목별 수정** — 각 섹션 "수정" → 해당 단계만 작성 폼으로 진입 → 저장 후 프로필 복귀.

**핵심 결정**

- **D1 — 현황 허브 역할을 HM-001로 이관, 이 페이지는 조회/수정 전용** (2026-06-14). HM-001을 로그인 후 랜딩 허브로 만들며 미팅·매칭 현황이 그쪽으로 갔다. 내 프로필이 허브를 중복할 이유가 없다. 미팅·매칭 현황 및 바로가기는 여기 두지 않는다.
- **D2 — 항목별 수정은 `/apply?step=N&from=profile` 딥링크.** F-BM-001이 정의한 5단계 폼을 재사용해, 수정하려는 섹션에 대응하는 단계(N)로 바로 진입한다. `from=profile` 파라미터로 "수정 진입(프로필 경유)"임을 알려, 완료 후 처음(`/apply`)이 아니라 `/profile`로 복귀시킨다. 새 수정 화면을 따로 만들지 않고 작성 폼을 단일 소스로 둔다.
- **D3 — 바이어 유형 표시.** 초청/일반에 따라 매칭 수락 규칙이 다름(ADR-0005). 본인이 자기 수신 동작을 예측할 수 있게 노출한다.
- **D4 — 조회는 읽기 전용, 변경은 작성 폼을 경유.** 이 페이지 자체에는 인라인 편집을 두지 않는다. 모든 쓰기는 BM-001 폼으로 위임 → 검증·저장 로직이 한 곳(작성)에만 존재해 두 페이지가 어긋나지 않는다.
- **D5 — 수정 저장도 작성과 동일한 원자적 경로(ADR-0009).** 이 페이지의 조회·수정은 **이미 승인된(`approved`) 참가자 프로필**을 대상으로 한다(제출 직후 `submitted` 검토 대기 동안은 수정이 잠기며, 운영이 보완을 요청하면 `changes_requested`로 풀려 재제출한다 — ADR-0009). 이미 `approved`(매칭 참가자)인 프로필을 고쳐도 데이터 저장은 작성 시와 같은 트랜잭션 규율을 탄다. 수정은 `application_status`를 되돌리지 않는다 — 한 번 승인된 바이어는 항목을 고쳐도 매칭 대상으로 남는다(반쪽 저장 방지·매칭 자격 유지·비강등).
- **접근 권한:** Buyer O(본인 프로필만) · Exhibitor X(참가사는 F-BM-005, `/exhibitor/profile`) · Organizer X. 현장(On-site) 바이어도 사전등록·초청 바이어와 동일하게 접근(미인증 사용자는 진입 불가 → `/login`).
- **아키텍처 경계(ADR-0008):** 조회·수정 저장 모두 Next.js → FastAPI API → RDS(경계 B, Next.js는 DB 직접 접속 안 함). 권한검사("이 회원이 이 프로필 주인인가")는 FastAPI 한 곳에서 Cognito JWT(JWKS/RS256) 검증으로 수행. 진입 전 인증 게이트는 딥링크 + DX Korea 인증(ADR-0007).

**식별된 deep modules** (격리 테스트 대상 후보)

- `profile-read` — 한 바이어의 `org_event_role`을 받아 조회용 프로필(기본정보·관심분야·상세니즈·예산/도입시기 + 바이어 유형 + 완성도)을 조립하는 읽기 모듈. 본인 소유 검증 포함, 타인 프로필 차단.
- `profile-edit-deeplink` — 섹션 → 단계(N) 매핑과 `/apply?step=N&from=profile` 링크 생성, 완료 후 복귀 경로(`from=profile` → `/profile`) 해석을 캡슐화. F-BM-001의 `profile-form-state`와 step 인덱스를 공유.

> 참고: 완성도 계산 규칙은 HM-001과 공유한다(별도 모듈 또는 공유 함수). 본 PRD에서 새로 정의하지 않고 HM-001 정의를 재사용한다.

## Testing Decisions

- **좋은 테스트의 기준:** 구현 세부가 아니라 **외부 동작**만 검증한다(컴포넌트 내부 상태가 아니라 "BM-001에서 3단계를 채우고 제출하면 그 값이 `/profile` 조회에 그대로 보인다", "예산 섹션 수정을 누르면 step=4로 열린다" 같은 관찰 가능한 결과).
- **테스트 대상 모듈:**
  - `profile-read` — 조회 조립이 작성된 값을 빠짐없이 반영하는지 / 미작성 항목이 "비어 있음"으로 구분되는지 / **본인 외 프로필 접근이 차단되는지**(권한) / 바이어 유형이 `buyer_subtype`대로 표시되는지.
  - `profile-edit-deeplink` — 각 섹션 "수정"이 올바른 step으로 매핑되는지 / 완료 후 `from=profile`이면 `/profile`로 복귀하는지(작성 신규 진입과 분기).
  - 수정→저장 회귀: 한 단계만 고치고 저장하면 **그 단계 값만 바뀌고 나머지는 보존**되며, `application_status`가 `approved`에서 되돌아가지 않는지(매칭 자격 유지·비강등 — F-BM-001 `participant-promotion`와 경계 공유).
- **Prior art:** 앱 코드가 아직 0인 그린필드. F-BM-001(작성)이 첫 수직 슬라이스의 테스트 기준선을 세우므로, 본 PRD는 그 위에 **조회·수정 진입의 외부 동작 테스트**를 얹는 형태로 따라간다. 별도 외부 의존이 없어 작성 슬라이스 직후의 통합 테스트로 적합.

## Out of Scope

- **6/17 컨셉 데모는 목업** — 프로필 조회/수정 UI 시연만. 실제 조회·저장은 BM-001 작성 슬라이스 구현에 종속.
- **현황 허브(미팅·매칭 현황, today 일정, 알림, 바로가기)** — 전부 F-HM-001(홈 대시보드) 소관. 이 페이지에 중복 배치하지 않는다(D1).
- **프로필 완성도 계산 규칙 자체의 정의** — HM-001과 공유하는 규칙을 재사용. 규칙 정의·확정은 HM-001에서.
- **인라인 편집(이 페이지 내 직접 수정)** — 도입하지 않음. 모든 쓰기는 BM-001 폼으로 위임(D4).
- **바이어용 문서 업로드 Smart Fill** — Smart Fill은 참가사 측(F-BM-002)에 한정(ADR-0008). 바이어 측 자동완성은 범위 밖.
- **관심분야 키워드 카테고리 체계 확정** — 미정(CTO 협의, fit score 선행). 조회·수정 표시는 BM-001과 동일하게 잠정 자유 입력 기준.
- **참가사 프로필 조회/수정** — F-BM-005(`/exhibitor/profile`) 소관.

## Further Notes

- 이 페이지는 **F-BM-001(바이어 프로필 작성)의 사후 짝**이다. 작성 폼(5단계)을 단일 소스로 재사용하므로, 단계 구성·검증·저장 규율의 진실원천은 F-BM-001이다. 본 PRD는 그 위에 조회와 항목별 수정 진입을 정의한다.
- 바이어 유형 표시는 ADR-0005(수락 모델: 초청=즉시 확정 / 일반=수락 필요)의 사용자 인지면이다.
