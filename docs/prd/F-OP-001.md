# F-OP-001: 매칭 현황 대시보드

> 운영사가 전시회 전체의 비즈매칭·미팅 현황을 **한 화면에서 파악하는 읽기 전용 대시보드**. 운영사 로그인 직후 랜딩 페이지이며, 등록자/참가자 규모·미팅 상태 분포·전체 포화배정 현황·0건 참가사 같은 **운영 모니터링 지표만** 노출한다(성과측정 지표는 NABI 내부 분석으로 분리).

## Problem Statement

운영사(Organizer) 입장에서:

- 전시회 전체가 지금 어떤 상태인지 — 명단에 몇 곳이 들어와 있고, 그중 실제로 비즈매칭에 참여(프로필 제출)한 곳은 몇 곳인지, 미팅은 얼마나 잡혔고 그중 예정·완료·취소·노쇼가 각각 얼마인지 — 를 한눈에 볼 곳이 없으면 운영 판단이 느려진다.
- 행사의 성과 입증선은 "0건 참가사 없음"인데, 어떤 참가사가 미팅이 한 건도 없는지 따로 찾아다녀야 하면 전체 포화배정을 언제 다시 돌려야 할지 판단이 어렵다.
- AI 전체 포화배정은 1회성이 아니라 반복 실행이라, 마지막으로 언제·몇 회차를 돌렸는지, 지금 검토 대기 중인 Draft가 있는지, 빈 슬롯이 얼마나 남았는지를 모르면 재실행 타이밍을 놓친다.
- 화면마다 흩어진 숫자를 모아 봐야 하면, 정작 행동(배정 재실행·명단 점검)이 어디서 필요한지 가려내기 어렵다.

## Solution

운영사 입장에서:

- 로그인하면 바로 **전체 현황 요약 대시보드**에 도착한다. 등록자 규모와 그중 비즈매칭 참가자(승인 완료) 규모를 나란히 보여줘 "명단만 vs 실제 참여"를 구분해 읽는다(ADR-0009).
- 미팅을 **상태별로 분포**(예정·완료·취소·노쇼)와 **시간대별 분포**로 묶어 보여줘, 행사 부하·혼잡도와 진행 상태를 한 화면에서 가늠한다.
- **0건 참가사 수**와 **슬롯 사용률**을 현황으로 띄워, 행동이 필요한 지점(전체 포화배정 재실행·단일 재트리거)을 바로 알아챈다. 실행은 이 화면이 아니라 OP-005/OP-003에서 한다.
- **전체 포화배정 현황**(최근 실행 시각·회차·Draft 검토중 여부)을 표시해, 반복 실행 구조에서 재실행 타이밍을 판단한다(ADR-0006).
- 대시보드는 **읽기 전용**이다 — 현황 파악에 집중하고, 액션은 명단(OP-002)·전체 배정(OP-005)·단일 기업(OP-003)으로 보낸다.

## User Stories

1. As an 운영사, I want 로그인 직후 전체 현황 대시보드에 바로 랜딩하기를, so that 별도 홈을 거치지 않고 곧장 운영 상태를 파악한다.
2. As an 운영사, I want 명단에 적재된 등록자(Registrant) 수를 보기를, so that 주관사 스냅샷이 얼마나 들어와 있는지 규모를 안다.
3. As an 운영사, I want 비즈매칭 참가자(application_status=approved) 수를 등록자 수와 나란히 보기를, so that "명단에만 있음"과 "실제 매칭 참여"를 구분해 참여율을 읽는다.
4. As an 운영사, I want 참가자 수를 참가사/바이어 역할별로 나눠 보기를, so that 공급(참가사)과 수요(바이어)의 비대칭을 파악해 배정 전략을 가늠한다.
5. As an 운영사, I want 전체 비즈매칭(미팅) 건수를 보기를, so that 전체 매칭 볼륨을 한눈에 안다.
6. As an 운영사, I want 미팅 상태 분포(예정·완료·취소·노쇼)를 보기를, so that 행사 진행 상태와 이탈 규모를 가늠한다.
7. As an 운영사, I want 완료 매칭 수를 보기를, so that 행사 중 실제로 성사된 미팅 규모를 안다.
8. As an 운영사, I want 노쇼율(noshow / (completed + noshow))을 보기를, so that 행사 중 노쇼 부담을 파악한다.
9. As an 운영사, I want 완료 대비 미팅 후기 작성률을 보기를, so that 리뷰 수집 현황(F-MY-002)을 파악한다.
10. As an 운영사, I want 시간대별 미팅 분포(예정·완료·노쇼) 그래프를 보기를, so that 운영 부하·혼잡 시간대를 파악해 현장 인력을 배치한다.
11. As an 운영사, I want 슬롯 사용률(배정된 슬롯 / 전체 가용 슬롯)을 보기를, so that 빈 슬롯이 얼마나 남았는지 보고 재배정 필요를 판단한다.
12. As an 운영사, I want 미팅이 0건인 참가사 수를 보기를, so that 효과 입증 최저선(0건 없음)을 추적하고 전체 포화배정 재실행 필요를 판단한다.
13. As an 운영사, I want 전체 포화배정의 최근 실행 시각·회차를 보기를, so that 반복 실행 구조에서 마지막으로 언제 돌렸는지 안다.
14. As an 운영사, I want 검토 대기 중인 Draft 배정이 있는지 표시되기를, so that 확정 게이트에서 멈춰 있는 실행을 놓치지 않는다.
15. As an 운영사, I want 모든 지표가 시기(신청기간 vs 행사진행)에 따라 자연스럽게 값만 변하기를, so that 단계 전환 없이 같은 화면을 계속 본다.
16. As an 운영사, I want 대시보드에서 직접 매칭 실행·리마인더 발송 같은 액션을 하지 않기를, so that 현황 파악과 실행 책임이 섞이지 않고 액션은 OP-002/005/003에서 일관되게 수행된다.
17. As an 운영사, I want 대시보드를 모바일에서도 읽기를, so that 현장에서 휴대폰으로 빠르게 현황을 확인한다.
18. As an 운영사(master), I want 전체 지표에 접근하기를, so that 행사 전반을 책임지고 모니터링한다.

## Implementation Decisions

**진입 경로**
- 운영사 로그인 → `/organizer` 랜딩(로그인 후 바로 대시보드). 좌측 네비게이션 "대시보드" 메뉴로도 진입.
- 구 OP-000(주최사 홈)은 OP-001에 통합 — KADEX with DX Korea 2026은 단일 이벤트라 별도 홈 불필요.

**단일 레이아웃(단계 구분 없음)**
- 비즈매칭 기간(8/26~9/11)과 행사 진행(9/16~19)을 별도 뷰로 나누지 않는다. 모든 지표를 항상 표시하되 시기에 따라 값이 자연스럽게 변한다. 단계 분기는 복잡성만 키운다.

**지표 위젯 구성(운영 모니터링 전용)**

| 위젯 | 정의 | 비고 |
|------|------|------|
| 등록자 수 | `registrants` 적재 건수(이벤트별) | 명단 규모(ADR-0009) |
| 비즈매칭 참가자 수 | `application_status='approved'` 인 role 수 | "매칭 대상" 규모. 역할별(참가사/바이어) 분할(ADR-0009) |
| 전체 비즈매칭 수 | 활성 미팅 건수(`proposed`+`accepted`+`completed`) | 전체 볼륨 |
| 상태 분포 | 예정·완료·취소·노쇼 비율 | `meetings.status` 집계 (예정 = `proposed`+`accepted`) |
| 완료 매칭 수 | `status='completed'` 건수 | 행사 중 활성 |
| 노쇼율 | `noshow / (completed + noshow)` | 행사 중 활성 |
| 후기 작성률 | 완료 대비 미팅 후기 작성 비율 | 리뷰 수집 현황(F-MY-002) |
| 시간대별 미팅 그래프 | 시간대별 미팅 분포(예정·완료·노쇼) | 운영 부하·혼잡도 |
| 슬롯 사용률 | 배정 슬롯 / 전체 가용 슬롯 | 빈 슬롯 파악 → OP-005 재실행/OP-003 재트리거 연결 |
| 0건 참가사 수 | 미팅 0건인 `approved` 참가사 수 | 효과 입증 최저선(ADR-0006 보장 라운드 목표) |
| 전체 포화배정 현황 | 최근 실행 시각·회차 + Draft 검토중 여부 | `saturation_batch_runs` 기반(ADR-0006) |

- 가용 슬롯 총량은 하드코딩하지 않고 `event_schedule_settings`(운영 시작/종료·점심 블록·슬롯 길이·최소 보장 N)에서 파생한다(ADR-0006).

**새 상태흐름 반영(ADR-0005, 옛 opt-in 흔적 제거)**
- 상태 분포는 **opt-out 즉시 확정 모델**을 전제로 집계한다. "예정"은 수락대기(`proposed`)와 확정(`accepted`)을 함께 묶은 운영 관점 묶음이며, 일반 바이어 수신 건에만 `proposed`가 생긴다(전체 포화배정의 참가사 측·초청 바이어 수신 건은 거부 단계 없이 `accepted`로 직행 — ADR-0005).
- **수락 규칙은 출처(provenance)가 아니라 받는 쪽 유형으로 결정**되므로, 대시보드는 provenance 축으로 수락 상태를 해석하지 않는다. "즉시확정/수락대기 비중" 같은 분해는 성과측정이라 대시보드에 노출하지 않는다(아래 D8).
- 옛 "AI는 제안만 한다"식 서술·opt-in 기반 전환율 지표는 제거하고 ADR-0005 상태흐름으로 보정한다.

**전체 포화배정 현황(ADR-0006)**
- 전체 포화배정은 반복 실행 가능(추가 전용·비파괴)이므로, 대시보드는 `saturation_batch_runs`의 최근 회차(`run_number`)·실행 시각·`status`(draft/confirmed/discarded)를 현황으로 가시화한다. 검토 대기 Draft가 있으면 명시한다(확정 게이트는 OP-005에서).

**경계 B(ADR-0008)**
- 모든 지표는 집계 결과다. Next.js는 RDS에 직접 접속하지 않고 **FastAPI 집계 엔드포인트만 호출**한다(경계 B — FastAPI가 DB·권한검사 단일 소유). 대시보드는 읽기 전용이라 쓰기 경로가 없다.

**읽기 전용**
- 대시보드에서 액션(매칭 실행·리마인더 발송)은 제공하지 않는다. 명단·프로필은 OP-002, 전체 배정은 OP-005, 단일 기업 배정은 OP-003에서 수행한다.

**접근 권한**
- Organizer(**master-for-this-event**) O(전체 지표) · Organizer(sub) **X** · Buyer/Exhibitor/Visitor X.
- **sub(무역관)를 제외하는 근거(ADR-0012/0013 — 확정):** 권한등급(master/sub)은 계정 전역이 아니라 **계정×행사 단위**이고, sub의 관할은 **자기가 현재 관리하는 바이어 집합**으로 좁혀진다. 본 대시보드는 **행사 전역 집계**라 sub 관할을 넘어서므로 열지 않는다. ADR-0012는 운영자 콘솔(`/organizer/*`)의 **기본선을 master 전용**으로 두고 무역관(sub) 전용 콘솔을 별도 라우트 네임스페이스의 후속 슬라이스로 분리했다 — 본 대시보드는 그 기본선을 그대로 따른다(sub에게 **관할 한정** 뷰를 여는 예외는 명단 관리 OP-002 D20뿐). 가드는 등급 하드코딩(`permission_level in (...)`)이나 광역 `require_organizer`가 아니라 **capability를 표현하는 `require_event_master`** 로 짓는다(FastAPI 단일 지점, ADR-0008 경계 B).

**식별된 deep modules** (격리 테스트 대상 후보)
- `ops-metrics-aggregation` — 등록자/참가자 수·미팅 상태 분포·완료/노쇼·후기율·슬롯 사용률·0건 참가사를 이벤트 단위로 계산하는 순수 집계 모듈. 입력은 이벤트 ID, 출력은 지표 묶음. UI와 분리되어 단순·안정 인터페이스.
- `saturation-run-status` — `saturation_batch_runs`에서 최근 회차·실행 시각·Draft 검토중 여부를 도출하는 현황 모듈(ADR-0006).

## Testing Decisions

- **좋은 테스트의 기준:** 위젯 렌더링 같은 구현 세부가 아니라 **집계의 외부 동작**을 검증한다. 예: "승인(`approved`)이 아닌 상태(`registered`·`submitted`)는 참가자 수에 잡히지 않는다", "취소된 미팅은 슬롯 사용률에서 빠진다", "미팅 0건인 approved 참가사만 0건 참가사로 집계된다", "최근 회차가 Draft면 검토중으로 표시된다".
- **테스트 대상 모듈:**
  - `ops-metrics-aggregation` — registered/submitted/approved 분리(참가자=approved, ADR-0009), 상태 분포 묶음(예정=proposed+accepted), 완료/노쇼·후기율·슬롯 사용률·0건 참가사. opt-out 상태흐름 전제(ADR-0005)를 집계가 올바로 반영하는지.
  - `saturation-run-status` — 최근 회차 선택, Draft 검토중 판정, 미실행(0회차) 상태.
- **Prior art:** 앱 코드가 아직 0인 그린필드라 기존 집계 테스트 선례 없음. 본 PRD의 두 모듈이 운영 집계 테스트의 기준선이 된다. 외부 의존 없이 DB 상태→지표 변환만 검증하면 되어 통합 테스트 출발점으로 적합하다.

## Out of Scope

- **6/17 컨셉 데모는 목업** — 실제 데이터 연동 없이 UI만 시연. 집계 엔드포인트 구현은 이 슬라이스 범위.
- **성과측정 지표(NABI 내부 분석으로 분리)** — opt-out 전환율, 즉시확정/수락대기 비중, 수락대기→수락 전환율 등 효과 입증 지표는 데이터만 수집하고 운영자 대시보드에 노출하지 않는다(D8, 2026-06-14).
- **적합도(fit score) 기반 지표** — 적합도 정의 미해결(키워드 카테고리 체계, CTO 협의 — CONTEXT "Flagged ambiguities"). 적합도 분포·매칭 품질 지표는 fit score 확정 후.
- **장소(Meeting Venue) 관련 지표** — 룸/테이블 배정 현황 지표는 장소 배정 방식 확정 후.
- **대시보드 내 액션** — 매칭 실행·리마인더 발송·명단 편집은 OP-002/005/003 소관. 본 페이지는 읽기 전용.
- **sub(무역관) 콘솔** — sub 권한 모델 자체는 **ADR-0012/0013으로 확정**됐다(계정×행사 master/sub + 바이어 소유권 관할). 다만 sub 전용 화면은 별도 라우트 네임스페이스의 후속 슬라이스 소관이며, 본 대시보드는 master 전용이라 sub 뷰를 두지 않는다.
