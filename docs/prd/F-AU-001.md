# F-AU-001: 통합 로그인

> 모든 사용자(운영사·참가사·바이어)가 진입하는 **단일 로그인 화면**. 주관사 명단을 미리 적재해두고, **딥링크 진입 + DX Korea 인증 API 아이디/비번 검증**으로 본인을 확인한 뒤 **역할에 따라 자동 분기**한다. 최초 진입 시 **NABI 약관 동의를 받고 게이트된 NABI 계정을 발급**한다.

## Problem Statement

참가사/바이어(주 actor) 입장에서:

- 비즈매칭을 쓰려면 먼저 "내가 그 명단의 그 사람"임을 증명해야 한다. 그런데 별도 회원가입을 또 하게 만들면 번거롭고, 일회성 전시회에 가입 절차는 과하다.
- 초대 링크만 받으면 그 링크가 포워딩·유출됐을 때 제3자가 내 자격으로 들어올 수 있다 — 방산 정보라 신원이 새는 게 특히 위험하다.
- 나는 참가사일 수도, 바이어일 수도, 둘 다일 수도 있는데 로그인할 때 그걸 매번 고르고 싶지 않다. 들어가면 알아서 내 화면이 나와야 한다.
- 방산 민감정보를 다루는데 동의를 받았다는 기록 없이 내 정보가 처리되면 안 된다.

운영사 입장에서:

- 운영사는 주관사 명단에 없는 내부 인원이다. 참가사·바이어와 같은 화면으로 들어가되 내 계정으로 인증하고 운영 화면으로 가야 한다.

## Solution

참가사/바이어 입장에서:

- **딥링크(토큰)** 로 `/login`에 도착해 **DX Korea 아이디/비번을 1회 검증**하면 본인 확인이 끝난다 — NABI에 별도 가입할 필요가 없다. 신원의 닻이 "링크"가 아니라 "주관사가 보유한 DX Korea 회원 계정"이라, 링크가 새도 그 사람의 아이디/비번을 모르면 못 들어온다.
- 검증에 성공하면 **반환된 회원ID로 미리 적재된 내 명단 레코드에 매핑**되고, 그 레코드의 **역할로 자동 분기**된다 — 참가사/바이어는 **`/welcome`(HM-002, 비즈매칭 모집)**, 운영사는 `/organizer`(OP-001). (`/welcome`이 신청기간·승인 상태를 보고 본 서비스 `/`(HM-001) 입장 여부를 판정 — FE ADR-0002.)
- **최초 진입 시 NABI 약관 동의를 1스텝으로** 받고(서비스 이용·개인정보·**민감정보(방산)** 등 항목별), **게이트된 NABI 계정(Cognito)** 을 발급한다. 이후 로그인은 NABI 계정 세션으로 처리된다.

운영사 입장에서:

- **같은 로그인 화면**을 쓰되, 명단(roster) 밖 **NABI/주최 내부 계정**으로 인증한다. 딥링크·DX Korea 인증·명단 매핑 대상이 아니며, 로그인 후 역할 분기로 운영 화면으로 간다.

## User Stories

1. As a 참가사/바이어, I want 딥링크를 누르면 바로 로그인 화면에 도착하기를, so that 주소를 외우거나 검색하지 않고 한 번에 진입한다.
2. As a 참가사/바이어, I want DX Korea 아이디/비번으로만 본인 확인이 끝나기를, so that NABI에 별도 회원가입을 다시 하지 않는다.
3. As a 참가사/바이어, I want 내 딥링크가 남에게 전달돼도 그 사람이 내 계정으로 못 들어오기를, so that 방산 정보가 링크 유출로 새지 않는다.
4. As a 참가사/바이어, I want 인증 성공 시 내 명단 정보(기관·담당자·역할)가 이미 연결돼 있기를, so that 같은 정보를 또 입력하지 않는다.
5. As a 참가사/바이어, I want 로그인 후 내 역할에 맞는 화면으로 자동 분기되기를, so that 참가사/바이어 화면을 직접 고르지 않는다.
6. As a 참가사이면서 바이어인 사용자, I want 두 역할을 다 가진 채로 들어가기를, so that 한 계정에서 양쪽 기능을 모두 쓴다.
7. As a 최초 진입 사용자, I want 약관(서비스·개인정보·민감정보)을 항목별로 확인하고 동의하기를, so that 무엇에 동의하는지 알고 진행한다.
8. As a 최초 진입 사용자, I want 약관 동의 후 NABI 계정이 자동 발급되기를, so that 추가 가입 단계 없이 곧바로 서비스로 들어간다.
9. As a 재방문 사용자, I want 이미 발급된 NABI 계정 세션으로 로그인되기를, so that 약관 동의를 매번 반복하지 않는다.
10. As a 참가사/바이어, I want 아이디/비번이 틀렸을 때 명확한 안내를 받기를, so that 무엇을 고쳐야 할지 안다.
11. As a 참가사/바이어, I want 만료·무효 딥링크로 들어가면 그 사실을 안내받기를, so that 막연히 실패하지 않고 다음 행동을 안다.
12. As a 운영사, I want 같은 로그인 화면에서 내부 계정으로 인증하기를, so that 별도 운영 전용 진입점을 따로 찾지 않는다.
13. As a 운영사, I want 로그인 후 운영 대시보드(OP-001)로 분기되기를, so that 참가측 화면을 거치지 않고 바로 운영을 시작한다.
14. As a 운영사, I want 약관 동의·동의 시각·약관 버전이 감사 가능하게 저장되기를, so that 방산 민감정보 처리 근거를 추후 증빙한다.
15. As a 미인증 사용자(QR 현장 진입자), I want NABI 서비스 페이지에 접근하려 하면 로그인으로 안내받기를, so that 딥링크 로그인으로 인증한 뒤 이용한다(게스트 탐색·자기전환 없음).
16. As a 모바일 현장 사용자, I want 로그인·약관동의가 휴대폰에서 막힘없이 되기를, so that 전시장에서 폰만으로 진입한다.

## Implementation Decisions

**진입 경로 / 인증 흐름 (ADR-0007)**
- 0. 사전 — 주관사 전체 신청자 스냅샷을 운영자가 OP-002에서 업로드 → **회원ID 키로 멱등 upsert** → `registrants` 적재 + `organizations`/`members`/`organization_event_roles` **eager 생성**(ADR-0009).
- 1. 진입 — 사용자가 **딥링크(긴 랜덤·만료 토큰)** 로 `/login` 도착.
- 2. 본인 확인 — **DX Korea 인증 API 규격에 맞춰 아이디/비번 1회 검증** → 성공 시 반환된 **회원ID로 적재 레코드 매핑**.
- 3. 약관·계정(최초만) — 최초 진입이면 **NABI 약관 동의 1스텝** → **게이트된 NABI 계정(Cognito 유저풀) 발급** → 회원ID·적재 레코드와 동일 키로 연결.
- 4. 세션 — NABI 계정 세션 발급(이후 로그인은 Cognito 세션으로 처리).
- 5. 분기 — 적재 레코드의 **역할로 자동 분기**: 운영사 → `/organizer`(OP-001), 참가사/바이어 → `/welcome`(HM-002, 비즈매칭 모집). 본 서비스 `/`(HM-001) 진입은 `/welcome`이 승인·신청기간 게이트로 판정(FE ADR-0002).

**사용자별 인증 소스**

| 사용자 | 인증 소스 | 비고 |
|--------|----------|------|
| 참가사 / 바이어 | 주관사 명단 import + 딥링크 + **DX Korea 인증 API(아이디/비번)** | 적재 레코드에서 역할 읽음. 회원ID로 매핑 |
| 운영사 | **NABI/주최 내부 계정**(소수, 별도 발급) | roster 밖. 같은 화면, 인증 소스만 내부 계정. 딥링크·DX Korea 인증·import 대상 아님 |
| Visitor | 로그인 대상 아님 | 미인증 사용자. 서비스 페이지 이용 불가 → 딥링크 로그인 필요(게스트 탐색·자기전환 없음, 2026-07-02 정책 변경) |

**핵심 설계 결정**
- **D1 — 데이터/인증 축 분리(ADR-0007).** 데이터는 주관사 API 일정에 안 묶이게 **파일 동기화(스냅샷 업로드 → 멱등 upsert)**, 신원검증만 **DX Korea 인증 API**로 라이브 연결.
- **D2 — 신원의 닻 = DX Korea 회원 계정.** 딥링크 단독으론 포워딩·유출 시 제3자 진입 가능 → 아이디/비번 검증으로 외부인 차단. 인증 성공 시 회원ID로 적재 레코드 매핑. (구버전 "등록 연락처 OTP"는 폐기 — ADR-0007/0008.)
- **D3 — 공개 자체 회원가입 없음, 단 게이트된 가입(ADR-0007).** 진입은 딥링크 + 당일 QR Visitor만. **DX Korea 검증 통과자만** 최초 진입 시 약관동의 후 NABI 계정을 발급받는다(공개 가입 아님).
- **D4 — 최초 약관동의 v1 범위 승격(ADR-0007).** 구버전의 "약관 v1 미구현(backlog)"을 v1 범위로 끌어올린다 — 방산=민감정보라 처리 근거가 필수. 항목별 분리 동의(필수/선택)로 받고 버전·시각을 보존.
- **D5 — 운영사도 같은 로그인 화면, 역할 분기.** 단일 진입점. 운영사는 roster 밖 내부 계정으로 인증.
- **D6 — 소스 교체 가능성 유지.** 추후 주관사 API 제공 시 "운영자 파일 업로드"만 "API pull"로 교체, 뒷단(upsert·키·매핑) 불변.
- **접근 권한:** 전원(미인증 진입 포함) O — 로그인 화면 자체는 인증 분기의 시작점이라 미인증 사용자도 접근한다. 단, 미인증 사용자는 로그인 없이는 서비스 페이지를 이용할 수 없다(게스트 탐색 없음 — 라우트 가드 → `/login`).

**아키텍처 경계 (ADR-0008 — 경계 B)**
- 로그인 화면은 Next.js, **모든 인증·세션·DB 접근은 Next.js → FastAPI API → RDS**. Next.js는 DB·Cognito·DX Korea API에 직접 붙지 않고 FastAPI를 경유한다.
- 신원검증은 **DX Korea 인증 API(아이디/비번)**. **Cognito는 OTP 발송자가 아니라 NABI 유저풀 + 세션/JWT 토큰 저장·검증(JWKS/RS256)** 역할만 맡는다.
- 권한검사·DB 자격증명은 FastAPI 한 곳에 집중. NABI 계정 ↔ DX Korea 회원ID ↔ `registrants` 레코드를 동일 회원ID 키로 매핑.
- 약관 동의 데이터는 ADR-0009의 3테이블에 저장: `consent_documents`(약관 문서·버전), `user_consent_states`(개인별 현재 동의 상태 마스터), `user_consent_history`(append-only 동의/철회 감사 로그).
- **HTTP 계약 = folded 로그인 트랜잭션(ADR-0011).** UI seam의 검증/동의/세션 3단계를 3개 공개 엔드포인트로 직역하지 않는다 — `issueSession(memberId, role)`을 노출하면 클라가 임의 신원으로 세션을 받는 인증 우회가 된다. 대신 `POST /api/auth/login/start`(재방문=즉시 세션 `succeeded` / 최초=`consent_required`+불투명 **Login Ticket**+약관문서) + `POST /api/auth/login/complete`(ticket+동의→동의 기록+세션). 회원ID·역할은 클라로 안 나가고 ticket 뒤 백엔드 보관. FE는 `startLogin`/`completeLogin`로 적응하고 백엔드가 seam에 맞추지 않는다.

**식별된 deep modules** (격리 테스트 대상 후보)
- `deeplink-token` — 딥링크 토큰 발급·검증(만료·무효·일회성) 규칙을 캡슐화.
- `dx-korea-verify` — DX Korea 인증 API 호출·아이디/비번 검증·회원ID 반환을 감싸는 어댑터(규격 미확정이라 경계 안에 격리해 교체 가능하게).
- `consent-capture` — 약관 항목별 동의 수집·버전 스냅샷·마스터/이력 기록(ADR-0009 3테이블)을 캡슐화.
- `session-issue` — 검증 성공 → NABI 계정(Cognito) 발급/조회 → 세션/JWT 발급을 캡슐화.
- `role-branch` — 적재 레코드의 역할을 읽어 최종 라우트(`/organizer` vs `/welcome`)를 결정하는 순수 분기. (참가사/바이어는 `/welcome`로 — 본 서비스 진입은 그 안에서 게이트 판정.)

## Testing Decisions

- **좋은 테스트의 기준:** 구현 세부가 아니라 **외부에서 관찰 가능한 동작**만 검증한다(예: "만료된 딥링크로 들어가면 진입이 거부된다", "최초 사용자는 약관동의를 거쳐야 세션이 난다", "운영사 계정은 `/organizer`로, 바이어는 `/welcome`로 분기된다"). 토큰 내부 포맷이나 컴포넌트 상태를 직접 들여다보지 않는다.
- **테스트 대상 모듈:**
  - `deeplink-token` — 유효/만료/위조 토큰의 진입 허용·거부, 일회성 소진.
  - `dx-korea-verify` — 아이디/비번 성공·실패 분기, 성공 시 회원ID 반환→적재 레코드 매핑(미확정 규격은 어댑터를 스텁으로 두고 계약만 검증).
  - `consent-capture` — 최초 진입 시 필수 약관 미동의면 진행 차단, 동의 시 마스터(`user_consent_states`) 갱신 + 이력(`user_consent_history`) append, 약관 버전·시각 스냅샷 보존.
  - `session-issue` — 최초=계정 발급+세션, 재방문=기존 계정 세션(약관 재요구 없음).
  - `role-branch` — 운영사/참가사/바이어/겸직 역할별 최종 라우트.
- **Prior art:** 앱 코드가 아직 0인 **그린필드** — 기존 테스트 선례 없음. 본 PRD 모듈이 인증 슬라이스의 첫 테스트 기준선이 된다. (외부 의존 DX Korea API는 어댑터 경계로 격리해 계약 테스트만 두고, 실제 호출은 규격 확정 후 통합 테스트로 승격.)

## Out of Scope

- **6/17 컨셉 데모는 목업** — 로그인 + 아이디/비번 검증 + 역할 분기 흐름만 시연. DX Korea 인증 API 미연동 시 목업 검증으로 대체.
- **미해결 블로커(주관사 의존, backlog):**
  - **DX Korea 인증 API 규격 미확정** — 엔드포인트·인증 방식·아이디/비번 검증 응답·회원ID 반환 여부. (`dx-korea-verify` 어댑터 경계로 격리해 진행.)

  - 명단 파일 전달 채널(이메일/공유드라이브/SFTP) 및 export 주기 합의.

- 역할 분기·prefill은 ADR-0009의 **eager 생성**(import 시점에 org/member/role 존재, 로그인은 read-only)을 전제로 한다. 로그인 시 행을 새로 만들지 않는다(동시 첫로그인 레이스 방지).
