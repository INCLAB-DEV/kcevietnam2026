# F-NV-001: 공통 네비게이션 셸 (글로벌 크롬)

> 로그인한 참가사·바이어·운영자가 **모든 화면에서 공유하는 단일 글로벌 셸** — 좌측 사이드바 nav + 상단 헤더 + 본문 영역. 역할별 메뉴 분기, 활성 경로 표시, 알림 벨 배지(NT-001), 그리고 **사이드바 접기**를 한곳에서 책임진다. 핵심 변경: 접기 동작을 "통째로 숨김(offcanvas)"에서 "아이콘 레일로 축소(icon)"로 바꿔 **접어도 아이콘으로 계속 이동**할 수 있게 하고, 접기 토글을 컨텐츠가 아니라 **nav에 속한 어포던스**로 둔다. 위치는 유지, 동작만 변경.

## Problem Statement

로그인한 사용자(참가사·바이어·운영자) 입장에서:

- 모든 화면이 **같은 좌측 네비게이션·헤더**를 공유해야 하는데, **사이드바 접기 토글이 컨텐츠 영역 헤더에 떠 있어** nav에 속한 기능처럼 보이지 않는다. "이 접기 버튼이 어느 영역을 접는 건지"가 직관적이지 않다.
- 사이드바를 접으면 **메뉴가 통째로 사라져**(offcanvas), 본문은 넓어지지만 **다른 화면으로 이동할 길이 끊긴다.** 다시 펴기 전에는 어디로도 못 간다.
- 화면 폭이 좁아지면(모바일·태블릿) 항상 펼쳐진 좌측 nav가 **본문 공간을 잡아먹는다.**
- 역할마다 보여야 할 메뉴가 다르다(바이어/참가사 ≠ 운영자, 운영자는 알림 없음). 이 분기가 **여러 곳에 흩어져 복제**되면 한쪽만 고쳐져 메뉴가 어긋난다.
- 미인증 사용자는 애초에 nav 화면(미팅·알림·프로필 등)에 진입할 수 없어야 한다 — 라우트 가드가 `/login`으로 보내므로 로그인 사용자 메뉴를 그릴 일이 없다(게스트 탐색 없음).
- 안 읽은 알림이 있는지 **다른 화면에 있어도 nav에서 인지**할 수 있어야 한다(NT-001 벨 배지).

## Solution

로그인한 사용자 입장에서:

- 모든 인증 페이지를 **단일 글로벌 셸(AppShell)** 로 감싼다 — 좌측 사이드바 nav + 상단 헤더 + 본문(`SidebarInset`). 페이지는 본문만 그리고 크롬은 셸이 책임진다(로컬 nav 중복 금지 — `frontend/CONTEXT.md` Nav/Chrome System).
- **접기 동작을 `offcanvas` → `icon`으로 바꾼다.** 접으면 사이드바가 사라지지 않고 **아이콘 레일로 축소**되어, 라벨은 숨되 **아이콘을 눌러 계속 이동**할 수 있다(접힘 상태에서 호버 시 라벨 툴팁). 접기/펴기 어포던스는 **nav에 속한 것** — 사이드바 가장자리 레일(`SidebarRail`)에서 토글하고, 헤더 트리거는 위치를 유지한다. **위치는 유지, 동작만 변경.**
- 화면이 좁으면(모바일) 아이콘 레일 대신 **오프캔버스 sheet 드로어**로 전환 — 좁은 폭에서 아이콘 레일은 본문을 압박하므로, 평소엔 숨고 트리거로 열리는 sheet가 맞다.
- **역할별 nav 항목은 단일 소스**에서 관리한다. 바이어/참가사는 대시보드·기업 탐색·미팅·알림·프로필, 운영자는 운영 대시보드·참가기업 관리·비즈매칭 배정(**알림 미제공**).
- **알림 벨 배지(NT-001)** — 안 읽은 개수를 알림 메뉴에 배지로 띄운다. 운영자는 알림 메뉴가 없어 숨김(미인증 사용자는 셸 자체에 진입하지 못함).
- **미인증 사용자는 nav 셸을 받지 않는다** — 라우트 가드가 `/login`으로 redirect한다. (구 경량 셸 `VisitorShell`(로그인 버튼 + 본문) 경로는 폐지 — 2026-07-02.)
- 접힘 상태는 **세션을 넘어 유지**되고(쿠키), 키보드 단축키(`Cmd/Ctrl+B`)로도 토글된다.

## User Stories

1. As a 로그인 사용자, I want 모든 화면에서 동일한 좌측 사이드바 nav와 상단 헤더를 보기를, so that 어느 페이지에 있든 길찾기 방식이 똑같아 혼란이 없다.
2. As a 참가사/바이어, I want 사이드바에서 대시보드·기업 탐색·미팅·알림·프로필로 이동하기를, so that 핵심 화면을 한 번에 오간다.
3. As a 운영자, I want 사이드바에서 운영 대시보드·참가기업 관리·비즈매칭 배정으로 이동하기를, so that 운영 업무 화면만 깔끔하게 본다.
4. As a 운영자, I want 알림 메뉴가 보이지 않기를, so that 운영자 수신 알림이 정의되지 않은 현재 상태와 nav가 일치한다.
5. As a 로그인 사용자, I want 지금 보고 있는 화면에 해당하는 메뉴가 활성으로 강조되기를, so that 내가 어디에 있는지 즉시 안다.
6. As a 로그인 사용자, I want 하위 경로(예: `/discover/123`)에서도 상위 메뉴(기업 탐색)가 활성으로 표시되기를, so that 상세 화면에서도 현재 섹션을 잃지 않는다 — 단 대시보드(`/`)는 정확히 일치할 때만 활성.
7. As a 로그인 사용자, I want 사이드바를 접기를, so that 본문 작업공간을 넓게 쓴다.
8. As a 사이드바를 접은 사용자, I want 접힌 뒤에도 **아이콘으로 메뉴 이동**을 계속하기를, so that 좁은 nav를 쓰면서도 길찾기가 끊기지 않는다.
9. As a 사이드바를 접은 사용자, I want 아이콘에 호버하면 라벨 툴팁이 뜨기를, so that 아이콘만으로 어떤 메뉴인지 확인한다.
10. As a 로그인 사용자, I want 접기/펴기 토글이 nav(사이드바)에 속해 보이기를, so that 어느 영역을 접는지 직관적으로 이해한다.
11. As a 로그인 사용자, I want 접힘 상태가 새로고침·재방문에도 유지되기를, so that 매번 다시 접지 않아도 된다.
12. As a 키보드 사용자, I want 단축키(`Cmd/Ctrl+B`)로 사이드바를 토글하기를, so that 마우스 없이 빠르게 작업공간을 조절한다.
13. As a 모바일 사용자, I want 좁은 화면에서 nav가 평소엔 숨고 트리거로 열리는 드로어(sheet)로 뜨기를, so that 작은 화면에서 본문이 가려지지 않는다.
14. As a 안 읽은 알림이 있는 사용자, I want nav 알림 메뉴에 안 읽은 개수 배지를 보기를, so that 다른 화면에 있어도 처리할 알림이 있음을 인지한다(NT-001).
15. As a 로그인 사용자, I want 사이드바 하단에서 내 이름·소속·연락처를 보고 로그아웃하기를, so that 내 계정 맥락을 확인하고 안전하게 빠져나간다.
16. As a 미인증 사용자, I want nav 화면(예: `/discover`)에 접근하면 로그인 화면으로 리다이렉트되기를, so that 인증 후에만 서비스를 이용한다(게스트 셸 없음).
17. As a 개발/운영 점검자, I want dev 계정 스위처(`?as=`)가 nav 이동 중에도 보존되기를, so that 역할 전환 점검 중 목록에서 튕기지 않는다(실연동 시 제거 — ADR-0008).
18. As a 사용자, I want 셸이 서버·클라이언트에서 동일하게 그려져 hydration 경고가 없기를, so that 첫 로드가 깜빡임 없이 안정적이다.
19. As a 화면을 넓혔다 좁혔다 하는 사용자, I want 폭 변화에 따라 사이드바와 sheet가 매끄럽게 전환되기를, so that 반응형 경계에서 nav가 깨지지 않는다.
20. As a 참가사/바이어, I want 사이드바 하단의 **'운영사무국 문의하기'** 한 줄을 눌러 전화·이메일을 펼쳐 보기를, so that 신청·미팅 중 막히면 별도 안내 페이지를 찾지 않고 즉시 사무국에 연락한다 — 내 연락처 블록과 나란히 같은 모양의 연락처 세트가 둘 겹쳐 보이지 않으면서. (운영자는 사무국 본인이므로 미노출.)

## Implementation Decisions

**셸 구성 (단일 글로벌 크롬)**
- **D1 — 모든 인증 라우트는 `AppShell`로 감싼다.** `SidebarProvider` + `AppSidebar`(좌측) + `SidebarInset`(상단 헤더 + 본문). 페이지는 본문만 렌더하고 크롬은 셸이 소유한다. 로컬 nav/헤더 중복 금지(`frontend/CONTEXT.md` Nav/Chrome System — *Avoid: 로컬 nav, 페이지별 헤더*).
- **D2 — 미인증 사용자는 셸 없이 `/login`으로 리다이렉트.** 로그인 사용자 사이드바(미팅·알림·프로필·로그아웃)는 미인증에 부적합하고, 미인증 사용자는 nav 화면 자체에 진입할 수 없다(라우트 가드 → `/login`, FE ADR-0002). 구 `VisitorShell`(로그인 버튼 + 본문 경량 셸) 경로는 폐지됐다(2026-07-02 정책 변경 — 게스트 탐색 없음).

**접기 동작 변경 (이 PRD의 핵심)**
- **D3 — 접힘 모드를 `collapsible="offcanvas"` → `collapsible="icon"`으로 변경(PC).** 접으면 사이드바가 화면 밖으로 사라지지 않고 **아이콘 폭 레일로 축소**된다. 라벨은 숨고 아이콘은 남아 **클릭 이동이 유지**되며, 호버 시 라벨 툴팁을 노출한다. 이것이 "접혔을 때도 아이콘으로 이동" 요구의 구현이다.
- **D4 — 접기/펴기 어포던스는 nav 소속.** 사이드바 가장자리 레일(`SidebarRail`)이 사이드바 경계에서의 토글을 제공하고, 헤더의 트리거(`SidebarTrigger`)는 **위치를 유지**한다. 사용자 의도("위치는 유지, 동작만 변경")대로, 옮기는 것은 위치가 아니라 동작(offcanvas→icon)이다.
- **D5 — 모바일은 sheet(오프캔버스 드로어) 유지.** 좁은 폭에서 아이콘 레일은 본문을 압박하므로, 모바일은 평소 숨김 + 트리거로 열리는 sheet로 전환한다(반응형 분기는 shadcn `useIsMobile` 경계). 아이콘 레일은 PC 전용 동작.
- **D6 — 접힘 상태 영속 + 단축키는 vendor(shadcn `ui/sidebar`)가 제공.** 쿠키(`sidebar_state`, 7일)로 세션 간 유지, `Cmd/Ctrl+B` 토글. 우리가 다시 구현하지 않고 prop(`collapsible`)으로 동작만 설정한다.

**역할별 nav 항목 (단일 소스화)**
- **D7 — 역할→nav 항목 매핑은 단일 소스로 통합한다.** 현재 `NAV_ITEMS`가 `components/layout/nav.tsx`와 `components/app-sidebar.tsx` **두 곳에 복제**돼 있다(라벨·href 동일, 아이콘 유무만 차이). 한쪽만 고쳐져 어긋나지 않도록 **단일 정의(라벨·href·아이콘)** 로 합치고, 양 컴포넌트가 그것을 소비한다.
- **D8 — 렌더되지 않는 `Nav` 컴포넌트를 정리한다.** `components/layout/nav.tsx`의 `Nav`는 앱 어디에서도 렌더되지 않는 사문(死文)이고(실제 nav는 `AppSidebar`), `nav.test.tsx`는 그 사문을 검증하고 있다. **테스트를 실제 셸(`AppSidebar`의 역할별 투영)로 재배치**하고 `Nav`는 제거하거나, 보존이 필요하면 `UserRole` 타입만 타입 모듈로 분리한다. (deepening: 검증 대상을 "실제로 그려지는 nav"로 옮긴다.)
- **D9 — 역할별 항목.** 바이어: 대시보드(`/`)·기업 탐색(`/discover`)·미팅(`/meetings`)·알림(`/notifications`)·프로필(`/profile`). 참가사: 동일하되 프로필은 `/exhibitor/profile`. 운영자: 운영 대시보드(`/organizer`)·참가기업 관리(`/organizer/members`)·비즈매칭 배정(`/organizer/forced-matching`). **운영자 알림 미제공** — 운영자 수신 알림 타입이 정의돼 있지 않다(되돌리려면 알림 타입부터 정의).

**활성 경로 판정**
- **D10 — `isActiveNav(pathname, href)` 순수 함수로 활성 판정.** 대시보드(`/`)는 **정확히 일치**할 때만 활성, 그 외는 **하위 경로 포함**(`/discover/123` → 기업 탐색 활성). 활성 항목은 `aria-current="page"`로 표시. 이 함수는 이미 `app-sidebar.tsx`에 export돼 있고 격리 테스트 대상이다.

**알림 벨 배지 (NT-001)**
- **D11 — 알림 메뉴에 안 읽은 개수 배지.** `useUnreadCount(orgId)`로 조직 공유 인박스의 안 읽은 개수를 구독해, `> 0`일 때만 `/notifications` 항목에 배지(개수만, 드롭다운은 v1 컷). 읽음 처리하면 실시간 감소. 미인증 사용자는 nav 셸에 진입하지 못해, 운영자는 알림 메뉴가 없어 자연히 숨김(ADR-0010).

**dev 계정 스위처 보존**
- **D12 — nav 링크에 `?as=`를 보존.** dev 역할 스위처(`?as=`)가 nav 이동 시 사라지면 운영자가 목록에서 튕긴다. 활성 표시는 bare href로 판정하고 `?as`는 실제 href 속성에만 덧붙인다(SSR 스냅샷=null → 하이드레이션 불일치 없음). **실연동 시 제거**(Cognito 세션 도입 — ADR-0008, SEC #57).

**운영사무국 상시 문의 (nav 하단 연락처)**
- **D14 — 사이드바 푸터에 '운영사무국 문의하기' 상시 진입점을 둔다(참가사·바이어 한정).** 내 정보(User Story 15) 바로 아래에 두되, 전화·이메일을 항상 펼쳐 두면 **내 연락처 블록과 같은 모양의 연락처 세트가 둘** 쌓여 지저분하고 내 개인정보 상시 노출 부담도 있다 → **한 줄 '운영사무국 문의하기'(헤드셋 아이콘)로 접고, 누르면 Popover로 조직명·전화(`tel:`)·이메일(`mailto:`)을 편다.** 접힘(아이콘 레일)에선 헤드셋 아이콘만 남고 클릭 시 동일 Popover가 뜬다. **운영자(=사무국 본인)에겐 숨긴다**(`role !== "organizer"`). Popover는 shadcn `ui/popover`(신규 추가, `radix-ui` 통합 패키지 래퍼). **연락처 값은 단일 소스**(`components/layout/nav.tsx`의 `SECRETARIAT_CONTACT`) — 프로토타입(apply/apply-seller)의 "정보 수정은 운영사무국에 문의" 블록과 동일 값. 현재는 placeholder(`02-xxxx-xxxx`, `support@dxkorea.kr`)이며 실제 대표번호·이메일 확정 시 이 상수만 교체한다. (사무국은 별도 DB 엔티티가 아니라 정적 설정값 — schema 영향 없음.)

**아키텍처 경계**
- **D13 — 세션·역할은 페이지에서 주입.** 셸은 `role`·`user`·`orgId`를 props로 받아 그린다(현재 mock 세션). 라우트 단위 인증 가드(미들웨어/서버 리다이렉트)는 본 PRD 범위 밖(아래 Out of Scope). 모든 데이터 접근은 FastAPI 경유(ADR-0008, 경계 B).

## Testing Decisions

- **좋은 테스트의 기준:** 컴포넌트 내부 상태가 아니라 **외부 동작**만 검증한다. 예: "운영자에겐 알림 메뉴가 보이지 않는다", "`/discover/123`에서 기업 탐색이 활성이다", "안 읽음 3건이면 알림 항목에 배지가 뜬다", "접은 뒤에도 아이콘을 누르면 해당 라우트로 이동한다".
- **테스트 대상 모듈(확정):**
  1. **역할→nav 항목 투영** — buyer/exhibitor/organizer가 각각 올바른 항목만 받는지, 운영자에 알림이 **없는지**, 참가사 프로필이 `/exhibitor/profile`인지. (순수 투영, 격리 테스트 적합. 현재 `nav.test.tsx`가 사문 `Nav`를 검증 중이므로 **실제 `AppSidebar`의 투영으로 재배치** — D8.)
  2. **활성 경로 판정 `isActiveNav`** — 대시보드(`/`)는 정확 일치만, 하위 경로(`/discover/123`)는 상위 메뉴 활성. 순수 함수라 입력→출력만 검증.
  3. **알림 배지 노출** — `unread > 0`일 때 `/notifications`에만 배지, `0`이면 미노출, 운영자는 항상 미노출(미인증 사용자는 셸에 진입 불가).
  4. **접힘=아이콘 이동 통합 테스트** — 접힌 상태(icon rail)에서 아이콘 클릭이 정상 라우팅되는지. vendor(shadcn) 의존도가 높아 비용 대비 가치는 낮지만, "접어도 이동 가능"이 이 PRD의 핵심 약속이므로 **회귀 방지용 1개**는 둔다.
- **Prior art:** `components/layout/nav.test.tsx`(역할별 메뉴 노출 패턴 — 단, 검증 대상을 실제 셸로 옮긴다), `lib/api-client/api-client.test.ts`. F-BM-001이 세운 "외부 동작 검증" 원칙을 따른다.

## Out of Scope

- **라우트 단위 인증 가드** — 미들웨어/서버 리다이렉트(미로그인 차단, 역할 불일치 차단)는 본 PRD 밖. 현재 셸은 페이지가 주입한 세션을 그릴 뿐. 서버측 role 필터·`?as` 제거는 SEC #57 소관.
- **실 Cognito 세션** — mock 세션을 실 JWT(JWKS/RS256, FastAPI 검증)로 교체하는 작업은 ADR-0007/0008·AU-001 후속.
- **알림 드롭다운** — nav 벨은 **개수 배지만**(v1). 드롭다운 미리보기·필터·모두읽음은 F-NT-001(`/notifications` 페이지) 소관.
- **모바일 hydration mismatch 버그(#58)** — 별개 버그 이슈에서 처리. 본 PRD는 D18(서버·클라 동일 렌더)을 목표로 명시하되 수정 자체는 #58과 조율.
- **프로토타입 크롬(`nabi-ui.css` / `nabi-nav.js`)** — `docs/prototypes/`의 정적 프로토타입용 nav는 별개 시스템(`docs/design/navigation.md`). 본 PRD는 **실제 React 셸(`AppShell`)** 을 다룬다. (`frontend/CONTEXT.md`의 "Nav/Chrome System" 서술은 프로토타입 기준이라 React 셸과 어긋남 — Further Notes 참조.)
- **사이드바 항목 자체의 신규 기능** — 각 목적지(대시보드 HM-001, 탐색 DV-001, 미팅 MY-001, 알림 NT-001, 운영 OP-*)는 각자 PRD 소관. NV-001은 **그 사이를 잇는 셸**만.
