# F-BM-005: 내 프로필 (참가사)

> 참가사(Exhibitor)가 비즈매칭 프로필을 **작성(F-BM-002) 후 전체 조회하고, 항목별로 수정**하는 페이지. Smart Fill로 자동 채워진 값을 확인·교정하는 자리이기도 하다. **현황 허브는 아니다** — 미팅·매칭 현황은 HM-001 홈 대시보드가 담당.

| 메타 | |
|------|------|
| Page ID / 기능 ID | BM-005 / F-BM-005 |
| 라우트 / 형태 | `/exhibitor/profile` / 페이지 |

| 관리지표 | 프로필 수정 빈도, 프로필 완성도, 수정 진입 후 저장 완료율 |

---

## Problem Statement

참가사 입장에서:

- 비즈매칭 프로필(F-BM-002 5단계)을 한 번 작성하고 나면, 내가 무엇을 어떻게 적었는지 **한눈에 다시 확인할 데가 없다**. 전시품목·강점·타겟 바이어가 매칭에 그대로 쓰이므로, 제출한 내용이 지금도 맞는지 점검하고 싶다.
- 전시품목이 추가되거나 회사 소개를 다듬고 싶을 때, **한 항목만 고치려고 5단계 폼 전체를 처음부터 다시 거치는 건 부담**이다. 고치려던 부분만 바로 열고, 고친 뒤엔 다시 프로필로 돌아오고 싶다.
- 작성 시 문서 업로드 Smart Fill로 **자동으로 채워진 값**(회사 소개, 전시품목 등)이 실제 내 정보와 맞는지 확신이 안 선다 — 자동 추출분을 사람 눈으로 검토하고 틀린 곳을 바로잡고 싶다.
- 미팅·매칭 현황까지 이 화면에서 같이 보여주면 정작 "내 프로필을 확인·수정한다"는 본래 목적이 흐려진다.

## Solution

참가사 입장에서:

- 내 프로필 페이지에서 **F-BM-002에서 작성한 전체 정보(기본정보·전시품목·회사소개+강점·타겟 바이어)를 한 화면에서 조회**한다. 매칭에 들어가는 입력값을 통째로 점검할 수 있다.
- 각 섹션의 "수정"을 누르면 **해당 단계만 바로 여는 딥링크**(`/exhibitor/apply?step=N&from=profile`)로 작성 폼의 그 단계로 진입하고, 저장하면 다시 내 프로필로 복귀한다. 전체 재작성 없이 한 단계만 고친다.
- Smart Fill로 **자동 채워진 값도 동일하게 조회·수정 대상**이다. 자동 추출분을 확인하고 틀린 곳은 항목별 수정으로 교정한다 — 자동완성은 초안일 뿐 최종 책임은 참가사 본인에게 있다.
- 이 페이지는 **조회/수정 전용**이다. 미팅·매칭 현황과 바로가기는 두지 않고 **HM-001 홈 대시보드**가 담당한다 — 허브 중복을 제거해 목적을 단순하게 유지한다.

## User Stories

1. As a 참가사, I want 작성한 프로필 전체(기본정보·전시품목·회사소개+강점·타겟 바이어)를 한 화면에서 조회하기를, so that 매칭에 들어가는 내 입력값을 통째로 점검한다.
2. As a 참가사, I want 각 섹션이 작성 폼의 5단계 구획과 같은 구조로 보이기를, so that 어디를 고치면 무엇이 바뀌는지 바로 파악한다.
3. As a 참가사, I want 각 섹션의 "수정"을 눌러 해당 단계만 바로 열기를, so that 전체 5단계를 다시 거치지 않고 한 단계만 고친다.
4. As a 참가사, I want 항목별 수정을 마친 뒤 자동으로 내 프로필로 복귀하기를, so that 수정 결과를 곧바로 확인하고 흐름이 끊기지 않는다.
5. As a 참가사, I want Smart Fill로 자동 채워진 값(회사 소개·전시품목 등)을 프로필에서 확인하기를, so that 문서에서 잘못 추출된 부분이 없는지 검토한다.
6. As a 참가사, I want 자동 채워진 값이 틀렸을 때 해당 단계로 들어가 직접 고치기를, so that 매칭에 부정확한 정보가 쓰이지 않는다.
7. As a 참가사, I want 사업자등록번호 같은 기본정보가 조회에 표시되기를, so that 등록 정보가 맞게 들어갔는지 확인한다.
8. As a 참가사, I want 전시품목·분야 키워드를 조회에서 한눈에 보기를, so that 바이어에게 어떻게 노출되는지 가늠한다.
9. As a 참가사, I want 타겟 바이어(만나고 싶은 유형·국적·기관 유형)를 조회에서 확인하기를, so that 매칭 방향 설정이 의도대로인지 점검한다.
10. As a 참가사, I want 본인 기업의 프로필만 보고 수정할 수 있기를, so that 다른 기업 정보에 접근하거나 노출되지 않는다.
11. As a 참가사, I want 같은 기업의 다른 멤버가 고친 최신 프로필을 조회하기를, so that 기업 단위로 일관된 최신 정보를 본다.
12. As a 참가사, I want 모바일에서도 프로필을 편하게 조회·수정하기를, so that 현장에서 휴대폰으로 빠르게 점검한다.
13. As a 참가사, I want 글로벌 네비게이션 "내 프로필" 또는 홈 대시보드의 "프로필 수정"에서 이 페이지로 진입하기를, so that 어디서든 일관된 경로로 내 프로필에 닿는다.
14. As a 참가사, I want 이 페이지에서 미팅·매칭 현황 대신 프로필에만 집중하기를, so that 확인·수정이라는 본래 목적이 다른 정보에 묻히지 않는다.

## Implementation Decisions

**진입 경로**
- HM-001 홈 대시보드 "내 기업 프로필 요약" → "프로필 수정" 클릭.
- 글로벌 네비게이션 "내 프로필" 메뉴.

**조회 / 항목별 수정**
- **D1 — 조회는 F-BM-002 5단계 구획을 그대로 반영.** 기본정보 · 전시품목 · 회사소개+강점 · 타겟 바이어 4개 섹션(+ 완료/제출 메타)을 작성 폼과 동일한 구조로 표시해, "여기를 고치면 작성 폼의 어느 단계가 열리는지"가 1:1로 대응되게 한다.
- **D2 — 항목별 수정은 `/exhibitor/apply?step=N&from=profile` 딥링크.** F-BM-002 작성 폼의 특정 단계만 연다. `from=profile` 쿼리로 "프로필에서 들어온 수정 모드"임을 알려, 저장 후 처음부터 끝까지 진행하는 대신 **내 프로필로 복귀**시킨다. (F-BM-002 D2와 짝)
- **D3 — Smart Fill 값도 일반 항목과 동일하게 취급.** Smart Fill(문서 업로드 추출, ADR-0008·F-BM-002 측)로 채워진 값은 저장된 프로필 데이터일 뿐이므로 별도 분기 없이 조회·수정한다. 교정도 같은 항목별 수정 딥링크를 쓴다 — 조회/수정 경로가 자동분/수동분을 구분하지 않는다.
- **D4 — 현황 허브 역할을 HM-001로 이관, 이 페이지는 조회/수정 전용.** (2026-06-14) HM-001을 로그인 후 랜딩 허브로 만들며 미팅·매칭 현황이 그쪽으로 갔다(CONTEXT Role-based Route — 첫 랜딩은 전원 공용 `/`). 내 프로필이 허브를 중복할 이유가 없어 미팅·매칭 현황과 바로가기는 두지 않는다.

**접근 권한**

| 사용자 유형 | 접근 | 비고 |
|------------|------|------|
| Exhibitor | O | 본인(소속 Organization) 프로필만 |
| Buyer / Visitor | X | 바이어는 F-BM-004(`/profile`) |
| Organizer | X | |

- **D5 — Organization 단위·플랫 권한(ADR-0002/0007).** 프로필은 기업 자산이라 같은 Organization 멤버는 동일 프로필을 조회·수정한다. 멤버 교체가 일어나도 막을 대상은 회사 밖 외부인뿐(인증은 ADR-0007 게이트가 담당).

**아키텍처 경계 (ADR-0008 경계 B)**
- **D6 — 조회·수정 모두 Next.js → FastAPI API → RDS.** Next.js는 RDS에 직접 접속하지 않는다. "이 멤버가 이 Organization 프로필 행에 접근 가능한가"라는 권한검사는 FastAPI 한 곳에 집중하고, Cognito JWT를 JWKS/RS256으로 검증한다(ADR-0008). 항목별 수정 저장도 F-BM-002와 동일한 API 경계를 통과한다.

**식별된 deep modules** (격리 테스트 대상 후보)
- `profile-view-model` — 저장된 프로필 데이터를 5단계 섹션 구조로 매핑하고, 각 섹션을 `step=N` 딥링크에 연결하는 조회 모델. (작성 측 `profile-form-state`의 읽기 대응)
- `section-edit-deeplink` — `/exhibitor/apply?step=N&from=profile` 딥링크 생성·해석과 "수정 후 프로필 복귀" 왕복 규칙을 캡슐화. F-BM-002와 공유 후보(바이어 측 F-BM-004와도 패턴 공통).

## Testing Decisions

- **좋은 테스트의 기준:** 구현 세부가 아니라 **외부 동작**만 검증한다. (예: "프로필 조회에 4개 섹션이 작성 폼 5단계와 같은 구획으로 나온다", "전시품목 섹션의 수정을 누르면 `step=2&from=profile`로 진입하고, 저장하면 다시 내 프로필로 돌아온다" 같은 관찰 가능한 결과.)
- **테스트 대상 모듈:**
  - `profile-view-model` — 저장된 프로필이 4개 섹션으로 올바로 매핑되고, 각 섹션이 정확한 `step` 번호 딥링크를 가리킨다. Smart Fill로 채워진 값도 동일하게 조회된다.
  - `section-edit-deeplink` — `/exhibitor/apply?step=N&from=profile` 진입 → 그 단계만 노출 → 저장 후 내 프로필 복귀. 잘못된 `step` 값 처리.
  - 접근 권한(경계 B): 본인 Organization 프로필만 조회/수정 가능, 타 기업·Buyer·Organizer 접근 거부 — FastAPI 권한검사 레벨에서 검증.
- **Prior art:** 앱 코드가 아직 0인 그린필드라 기존 테스트 선례 없음. F-BM-001/002가 첫 수직 슬라이스의 테스트 패턴 기준선이며, 본 PRD의 조회/수정 모듈은 그 작성 측 패턴의 **읽기·왕복 대응**으로 같은 기준선을 따른다.

## Out of Scope

- **6/17 컨셉 데모는 목업** — 프로필 조회/수정 UI 시연만, 실제 조회/저장 연동은 이 슬라이스 구현 범위.
- **미팅·매칭 현황 및 바로가기** — F-HM-001(홈 대시보드) 소관. 이 페이지에 두지 않는다(D4 중복 제거).
- **Smart Fill 추출 로직 자체** — 문서 업로드→S3→Claude 추출→prefill은 작성 측(F-BM-002 / ADR-0008) 범위. 본 PRD는 그 결과값의 조회·교정만 다룬다.
- **프로필 완성도 계산 규칙** — HM-001과 공유하는 계산 규칙은 미정(이후 과제).
- **분야 키워드 카테고리 체계 확정** — 미정(CTO 협의, 참가사 103개 전시품목 기반 도출). 조회는 작성된 잠정 자유 입력값을 그대로 표시.
- **매칭 로직 자체** — 배정·적합도는 ADR-0006 / OP-005 소관.

## Further Notes

- 항목별 수정의 진입 대상과 단계 구성은 **F-BM-002(참가사 프로필 작성)** 가 단일 소스다 — 단계 번호·항목이 바뀌면 F-BM-002를 따라 본 PRD의 섹션↔step 매핑도 갱신한다.
- 조회되는 프로필 데이터는 ADR-0009의 적재·게이트 모델을 전제로 한다: eager 생성으로 로그인 시 org/member/role이 존재하고, **승인 완료(`application_status='approved'`)된 비즈매칭 참가자**의 프로필이 조회·항목별 수정 대상이다. 제출 직후~승인 전(`submitted`, "주최국 확인 중")에는 폼이 잠겨 수정 불가이며, 이 단계의 안내는 HM-002(`/welcome`)가 맡는다(FE ADR-0002). 작성 미완 `registered`·반려 `rejected` 상태의 처리·표시도 F-BM-002/HM-002 흐름에서 다룬다.
