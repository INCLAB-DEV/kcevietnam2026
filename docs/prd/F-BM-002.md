# F-BM-002: 참가사 프로필 작성

> 참가사(Exhibitor)가 비즈매칭을 위해 **전시품목·강점·타겟 바이어를 입력하는 5단계 폼**. 매칭 정확도의 입력이자, "명단에만 있는 등록자"를 비즈매칭 참가자로 승격시키는 **신청서**다(승격 확정 트리거는 작성/제출이 아니라 **운영 승인 `approved`** — ADR-0009). 회사 자료(PDF/PPT/Word)를 올리면 AI가 폼을 미리 채워주는 **Smart Fill**로 작성 부담을 줄인다. **글로벌 nav 없는 단독 화면**(AppShell 밖) — 상태 안내·라우팅은 HM-002(`/welcome`)가 맡고 이 페이지는 **폼 작성/수정만** 책임진다(FE ADR-0002).

## Problem Statement

참가사 입장에서:

- 비즈매칭에서 맞는 바이어를 만나려면 우리 전시품목·강점·타겟을 충분히 전달해야 한다. 그런데 한 화면에서 한꺼번에 다 요구하면 부담스러워 중간에 포기하게 된다.
- 회사 소개서·제품 카탈로그처럼 **이미 만들어 둔 자료**에 필요한 내용이 다 들어 있는데, 그걸 보면서 폼에 일일이 옮겨 적는 건 시간 낭비다.
- 작성을 끝내야 매칭에 들어간다는데, 어디까지 채워야 "매칭 대상"이 되는지 명확하지 않으면 손이 안 간다.
- 이미 작성한 내용을 나중에 일부만 고치고 싶은데, 처음부터 다시 쓰게 만들면 안 된다.

## Solution

참가사 입장에서:

- 작성을 **5단계로 쪼갠 폼**으로 받는다. 단계마다 저장되어 중간에 나가도 **이어서 쓸 수 있다**. 부담이 줄고 완성도가 올라간다. **폼은 '저장'만 한다**(마지막 버튼 `저장하고 나가기` → `/welcome`) — 제출과 작성·저장을 명확히 구분한다(2026-06-30, FE ADR-0002 §4).
- 작성 초반에 **회사 자료(PDF/PPT/Word)를 올리면 AI가 전시품목·회사 소개·강점 등을 추출해 폼을 미리 채워준다(Smart Fill)**. 빈 칸을 처음부터 쓰는 대신, **채워진 초안을 검토·수정**만 하면 된다. 자료가 없으면 직접 입력으로 진행한다.
- 작성을 마치면 **`/welcome`에서 제출**한다(필수항목 충족 시 `제출하기` 노출, 확인 다이얼로그 후). 제출하면 **"주최국 확인 중"(검토 대기, `submitted`)** 상태가 되고, 운영(주최사/KOTRA) **승인(`approved`)** 을 받아야 비로소 **비즈매칭 참가자로 승격**되어 매칭 대상이 된다 — "명단에만 있는 등록자"에서 "실제로 매칭에 들어가는 참가사"로 바뀐다. (제출만으론 부족 — ADR-0009 2단계 게이트.)
- **제출하면 폼이 잠긴다**(검토 중 내용 표류 방지). 제출 후(`submitted`/`approved`/`rejected`)에 폼에 들어오면 편집 대신 **읽기전용 "신청서 보기"**(`ProfileView`, 돌아가기 버튼)로 렌더된다. 수정은 운영자가 보완 요청(`changes_requested`)으로 돌려보낼 때만 다시 열린다. 승인 후 항목별 수정은 내 프로필(F-BM-005) 경로(FE ADR-0002 §3).

## User Stories

1. As a 참가사, I want 프로필 작성이 여러 단계로 나뉘어 있기를, so that 한 번에 너무 많은 입력을 강요받지 않는다.
2. As a 참가사, I want 각 단계가 자동 저장되기를, so that 중간에 나가도 처음부터 다시 쓰지 않고 이어쓸 수 있다.
3. As a 참가사, I want 기업명·담당자 등 기본정보가 가능한 한 미리 채워져 있기를, so that 이미 등록 때 준 정보를 다시 입력하지 않아도 된다.
4. As a 참가사, I want 회사 소개서·카탈로그(PDF/PPT/Word)를 올리면 AI가 폼을 채워주기를, so that 자료에 있는 내용을 손으로 옮겨 적지 않아도 된다.
5. As a 참가사, I want AI가 자료에서 추출한 값을 제출 전에 검토·수정할 수 있기를, so that 잘못 뽑힌 부분을 바로잡아 내 의도대로 매칭에 반영한다.
6. As a 참가사, I want 자료가 없거나 자동추출을 원치 않을 때 직접 입력으로 진행하기를, so that Smart Fill에 의존하지 않고도 작성을 끝낼 수 있다.
7. As a 참가사, I want 전시할 제품/서비스를 제품별로 이름·사양과 함께 입력하기를, so that 바이어 탐색 화면에서 우리 제품이 개별적으로 보인다.
8. As a 참가사, I want 분야 키워드를 선택/입력하기를, so that 바이어 관심 분야와 우리 전시품목이 매칭된다.
9. As a 참가사, I want 회사 소개와 차별점/강점을 적기를, so that 바이어가 우리를 만날 가치를 판단할 수 있다.
10. As a 참가사, I want 만나고 싶은 바이어 유형·국적·기관 유형을 입력하기를, so that 우리가 원하는 방향으로 매칭이 이뤄진다.
11. As a 참가사, I want 사업자등록번호를 데이터 속성으로 입력하기를, so that 국내 법인 정보가 보강된다(없어도 작성은 막히지 않는다).
12. As a 참가사, I want 마지막 단계에서 입력 내용을 요약 확인하고 제출하기를, so that 잘못 적은 부분을 제출 전에 바로잡는다.
13. As a 참가사, I want 제출 후 "주최국 확인 중"(승인 대기) 안내와, 승인되면 비즈매칭 참가자가 됐다는 안내를 받기를, so that 제출이 끝이 아니라 운영 승인을 거쳐야 매칭 대상이 됨을 안다.
14. As a 참가사, I want 작성 중인 프로필이 아직 매칭에 노출되지 않기를, so that 완성되지 않은 정보로 매칭되지 않는다.
15. As a 참가사, I want 내 프로필에서 특정 단계만 골라 수정 화면으로 바로 진입하기를, so that 전체를 다시 거치지 않고 일부만 고친다.
16. As a 참가사, I want 작성을 모바일에서도 편하게 하기를, so that 데스크톱이 없는 상황에서도 막힘없이 입력한다.
17. As a 바이어(상대측), I want 참가사 프로필이 충분히 구조화되어 있기를, so that 어떤 참가사인지 판단해 미팅 가치를 가늠한다. (간접 — 수집 품질의 수혜자)

## Implementation Decisions

**진입 경로**
- HM-002(`/welcome`) — "신청서 작성하기"(`registered`)·"수정하기"(`changes_requested`) CTA로 이 폼에 진입. 로그인 직후 직접 착지가 아니라 welcome 경유(상태·기간 게이트는 welcome/route-guard가 판정).
- BM-005 내 프로필 — 항목별 수정 시 `/exhibitor/apply?step=N&from=profile` 딥링크로 특정 단계 진입(승인된 프로필 대상).

**폼 구성 (실제 DX Korea 셀러 등록폼 + KOTRA 요구사항 기준)**

> ⚠ 잠정 5단계(강점·타겟바이어 자유텍스트)는 **실제 등록폼으로 대체됐다**. 셀러는 **국문+영문
> 둘 다 필수**(이중 컬럼). **컬럼 단위 권위 정의는 `docs/db/bm-profile-fields.md`(§1~§7).**

| 단계(분할) | 항목(실제 등록폼) | 저장 위치 |
|---|---|---|
| 1. 기본정보 | 기업명(국/영)·사업자번호·홈페이지·대표번호·팩스·주소(국/영)·연매출(KRW)·직원수·상담언어·참가자 구분(8종) | `organizations`(식별), `exhibitor_profiles`, `org_event_role_org_types` |
| 2. 전시품목 | 제품 **복수**(제품명 국/영·카테고리 국/영·**HS코드**·사양)·전시품목 분야(방산 13 **고정**)·상품소개(국/영)+가격대 | `exhibitor_products`, `exhibitor_keywords`, `exhibitor_profiles` |
| 3. 회사소개 | 기업소개(국/영, 500)·로고/소개서 **파일** | `exhibitor_profiles`, `files` |
| 4. 타겟·담당자 | 선호 바이어 국가/기관·담당자 **복수**(국/영)·참가경로·KST 상담시간·KOTRA 회원·**초청 바이어 추천 복수** | `exhibitor_profiles`, `exhibitor_attendees`, `exhibitor_recommended_buyers` |
| 5. 완료 | 요약 확인 → 제출(submitted) | `organization_event_roles.application_status` |

- **D1 — 5단계 분할 폼.** 한 번에 받기엔 많아 단계별로 이탈을 줄이고 완성도를 확보한다.
- **D2 — 단계별 저장(이어쓰기).** 각 단계 완료 시 서버에 저장, 중간 이탈 후 재개 가능.
- **D3 — 항목별 수정은 `/exhibitor/apply?step=N&from=profile` 딥링크.** BM-005에서 특정 단계만 바로 연다.
- **D4 — 사업자등록번호는 데이터 속성, upsert 키 아님(ADR-0007).** 멱등 키는 전 레코드에 존재하는 회원ID. 사업자번호는 국내 법인에만 있어(해외업체 결측) 키로 쓰면 멱등성이 깨진다. 없어도 작성은 막히지 않는다.
- **D5 — 제출 → 운영 승인 → 매칭 노출(ADR-0009 갱신, 2단계).** 제출 시 `application_status`를 `submitted`로(작성 완료). **제출은 폼이 아니라 `/welcome`의 액션에서 트리거**(저장/제출 분리, FE ADR-0002 §4) — 폼은 드래프트 저장만. KOTRA 요구사항 "관리자 승인을 통해 최종 등록"에 따라 **주최사/KOTRA 승인 시 `approved`**로 전환되고, **매칭은 `approved`만 대상**(미승인 비노출). 상태머신은 `bm-profile-fields §6`.
- **D6 — 제출은 원자적 트랜잭션(ADR-0009).** 프로필 데이터 최종 저장과 `submitted` 전환을 하나의 트랜잭션으로 묶어, "status는 submitted인데 데이터 불완전"인 반쪽 상태를 구조적으로 막는다(승인은 별도 운영 슬라이스).
- **D12 — 단독 화면 + 저장/제출 분리 + 제출 후 잠금(FE ADR-0002).** 이 폼은 글로벌 nav 없는 단독 화면(AppShell 밖)으로, 상태 안내·라우팅·**제출**은 HM-002(`/welcome`)가 맡고 여기선 **폼 작성·저장**만 한다(마지막 버튼 `저장하고 나가기`). **편집 가능 = `application_status` ∈ {`registered`, `changes_requested`}**, 그 외(`submitted`/`approved`/`rejected`)는 **읽기전용 `ProfileView`("신청서 보기", 수정 버튼 없음, 돌아가기)**. 편집/읽기전용 판단의 단일 소스는 **세션 status(페이지 prop)** — mock STORE의 status가 아니다(dev `?status`는 세션 쿠키에만 반영). route-guard는 신청기간 중엔 전 status 진입 허용(폼이 잠금), 종료 후 잠금(→`/welcome`). 운영자가 `changes_requested`로 돌려보낼 때만 다시 편집(→ 재제출 시 `submitted`). 승인 후 항목별 수정은 BM-005 경로. (종전 BM-005 "신청기간이면 제출 후에도 수정 가능"을 반전.)

**Smart Fill (문서 업로드형 AI 자동완성 — ADR-0008)**
- **D7 — Smart Fill = 문서 업로드만.** PDF/PPT/PPTX/DOC/DOCX 회사 자료를 올리면 AI가 전시품목·회사 소개·강점 등을 추출해 2~3단계 폼을 prefill한다. (이전 프로토타입의 **회사 URL 스크레이핑·DART 자동조회는 제거** — Out of Scope 참조.)
- **D8 — Smart Fill 흐름.** 브라우저 →(presigned URL)→ S3 업로드 → FastAPI `/extract`가 S3 key로 파일을 읽어 Claude로 추출 → 구조화 JSON 반환 → 폼 prefill → 사용자 검토·수정 → 저장. AI 키는 backend에만 둔다.
- **D9 — 추출 결과는 초안일 뿐, 사용자가 검토·수정 후 확정.** 추출값을 그대로 제출하지 않고 폼에 채워진 상태로 보여줘 사용자가 고친 뒤 저장한다. prefill된 필드는 채워졌음을 표시한다.
- **D10 — 업로드 원본은 S3에 영구보관(ADR-0008).** 추출 후 즉시 삭제하지 않는다(프로토타입의 "추출 후 즉시 삭제" 문구 폐기). 방산 문서이므로 at-rest 암호화·접근통제·버전닝·보관기간 정책을 둔다.
- **D11 — Smart Fill은 선택 경로.** 자료가 없거나 원치 않으면 직접 입력으로 진행하며, 직접 입력만으로도 작성·승격이 완료된다.

**접근 권한**
- Exhibitor O(본인 프로필) · Buyer / Visitor X(바이어는 F-BM-001) · Organizer X.

**아키텍처 경계(ADR-0008 — 경계 B)**
- 폼은 Next.js, 저장/조회/추출은 Next.js → FastAPI API → RDS(경계 B, Next.js는 DB·S3·Claude에 직접 접속하지 않고 FastAPI만 호출).
- Smart Fill 컴퓨트(`/extract`)도 같은 FastAPI에 둔다.
- 진입 전 인증 게이트(딥링크 + DX Korea 인증 + 최초 시 NABI 약관동의·Cognito 계정 발급, ADR-0007/0008).

**식별된 deep modules** (격리 테스트 대상 후보)
- `profile-form-state` — 5단계 진행/단계별 저장/재개/단계 검증을 캡슐화하는 상태 모듈(F-BM-001과 공유 가능한 패턴).
- `smartfill-extraction-client` — 업로드된 문서를 FastAPI `/extract`로 보내 구조화 JSON을 받아 폼 필드에 매핑하는 추출 클라이언트(presigned 업로드 → 추출 요청 → prefill 매핑 경계).
- `participant-promotion` — 제출 시 프로필 저장 + `application_status=submitted`를 원자적으로 수행하는 트랜잭션 경계.

## Testing Decisions

- **좋은 테스트의 기준:** 구현 세부가 아니라 **외부 동작**만 검증한다(폼 컴포넌트 내부 상태가 아니라 "3단계까지 쓰고 나갔다 들어오면 1~3단계 값이 보존된다" 같은 관찰 가능한 결과).
- **테스트 대상 모듈:**
  - `profile-form-state` — 단계별 저장/재개, 미완 단계 검증, `/exhibitor/apply?step=N` 진입.
  - `smartfill-extraction-client` — 문서 업로드 → 추출 응답이 폼 해당 필드에 prefill되는가, 추출 실패/빈 응답 시에도 직접 입력으로 이어지는가, 사용자가 수정한 값이 추출 초안을 덮어쓰는가. (`/extract` 응답을 경계로 두고 검증 — Claude 호출 자체는 모킹.)
  - `participant-promotion` — **원자성**: 저장 또는 status 중 하나라도 실패하면 둘 다 롤백(반쪽 제출 불가). 제출은 `submitted`로 전환하되 **매칭 노출은 `approved`에서만**(운영 승인 후, ADR-0009).
- **Prior art:** 앱 코드가 아직 0인 그린필드라 기존 테스트 선례 없음 → 본 PRD의 모듈이 첫 테스트 패턴의 기준선이 된다. F-BM-001(바이어 측)과 폼 패턴을 공유하므로 두 PRD의 `profile-form-state`/`participant-promotion`이 동일 테스트 골격을 쓴다. (Smart Fill은 참가사 측에만 있어 `smartfill-extraction-client`는 본 PRD 고유.)

## Out of Scope

- **6/17 컨셉 데모는 목업** — 5단계 폼 UI와 Smart Fill UX 시연만, 실제 저장/추출/승격은 이 슬라이스 구현 범위.
- **회사 URL 스크레이핑·DART 자동조회 — 제거됨(ADR-0008).** 과거 프로토타입엔 URL에서 가져오기·DART 전자공시 자동조회 옵션이 있었으나, 외부 ToS·API 키·쿼터·스크레이핑 복잡도 블로커를 없애기 위해 **삭제**했다. Smart Fill은 문서 업로드 단일 경로만 유지한다.
- **(해결됨) 분야 키워드 분류체계** — 실제 등록폼이 **방산 13분야 고정 리스트**로 확정(`bm-profile-fields §1.1`). (구) "잠정 자유입력" 종료 — 시드 keywords + 조인. (제품 HS코드/카테고리는 별도 자유 입력.)
- **매칭 로직 자체** — 배정·적합도는 ADR-0006 소관.
- **실제 명단 컬럼 기반 prefill 매핑** — 주관사 명단 컬럼 구조 확정(선행 블로커) 후.

## Further Notes

- Registrant prefill은 ADR-0009의 eager 생성(로그인 시 org/member 존재)을 전제로 한다. 실제 prefill 필드 매핑은 주관사 명단 컬럼 확정(선행 블로커) 후 닫힌다. 그 전까지 명단 원본은 `registrants.raw jsonb`로 손실 없이 보존된다.
- Smart Fill 추출 산출물(원본 문서 S3 보관 + 추출 JSON)은 일회성 이벤트라 알고리즘 학습용이 아니라 **참가사 데이터 자산화·매칭 성과 측정**의 입력이다.
