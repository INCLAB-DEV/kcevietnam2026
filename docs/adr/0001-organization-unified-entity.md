# 참가사와 바이어를 Organization의 역할(role)로 통합

기존 계획에서는 참가사(Exhibitor)와 바이어(Buyer)를 별도 엔티티로 설계했으나, 실제 방산 전시회에서는 한 기업이 제품을 전시하면서 동시에 부품/소재를 구매 탐색하는 경우가 흔하다. Organization을 단일 엔티티로 두고 이벤트별로 역할(exhibitor, buyer, 또는 양쪽)을 부여하는 구조로 결정했다. DB 중복이 사라지고 매칭 풀이 넓어지는 반면, 향후 역할별로 완전히 다른 권한/플로우가 필요해지면 분기 로직이 복잡해질 수 있다.

## Considered Options

- **별도 엔티티**: Exhibitor 테이블, Buyer 테이블 분리. 직관적이지만 동일 기업이 양쪽에 중복 등록되고, 기업 정보 동기화 문제 발생.
- **역할 기반 통합 (채택)**: Organization + roles 배열. 한 기업이 복수 역할을 자연스럽게 가짐. 매칭 시 기업 단위로 동작.
