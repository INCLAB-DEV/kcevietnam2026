# 채팅 기반 탐색과 카드 기반 탐색은 상호 배타적 (카드 기본, 채팅 목표)

현장에서 바이어가 기업을 탐색하는 방식을 채팅 UI(NABI 대화 → 추천)와 카드 UI(검색/필터 → 리스트)로 설계했으나, 두 방식은 공존하지 않고 하나만 서비스에 들어간다. 카드 기반(플랜 B)을 기본으로 구현하고, 채팅 기반(플랜 A)이 가능하면 전환한다.

## Considered Options

- **공존**: 채팅 + 카드를 동시 제공하고 사용자가 선택. 진입점이 분산되고 UX가 복잡해짐. NABI의 정체성(대화형 AI 비서)이 희석됨.
- **상호 배타 (채택)**: 카드(플랜 B)를 기본 구현. AI 매칭 품질이 검증되면 채팅(플랜 A)으로 업그레이드. 서비스에는 하나만 노출.

## Consequences

- 카드 기반을 먼저 완성 — 확실한 베이스라인 확보
- 채팅 기반은 추가 구현 — 품질이 충분하면 카드를 대체
- 피처 플래그 또는 라우팅으로 전환 가능하게 구현
- 카드 모드에서는 NABI FAB/배너가 없음 (채팅으로의 동선 차단)
