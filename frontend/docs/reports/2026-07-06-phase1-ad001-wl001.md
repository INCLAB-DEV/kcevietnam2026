## 4. API 계약 (구현 기준)

### POST /api/buyer-profile — draft 부분저장

- 요청: `{ step: 1|2, draft: Partial<BuyerProfileDraft> }` — 해당 단계 소유 필드(STEP_FIELDS)만 반영, 미지의 키는 버림
- profileKey는 body가 아니라 **세션(orgId)에서 도출** (다른 프로필 키 지정 불가)
- **빈 값 저장 허용** — 부분저장은 제출 게이트가 아니다(#26 정합). [이전]/[저장하고 나가기]가 미완성 단계도 저장하므로 필수 미충족은 422가 아님
- 응답: `200 { success: true, draft }` / `400 invalid_json·invalid_step·invalid_draft` / `401` / `403`(바이어 아님) / `409 locked`(submitted·approved·rejected)

### POST /api/buyer-apply — 최종 제출

- 요청: `{ draft?: BuyerProfileDraft }` — 클라 store의 최종 draft를 실어 보냄(서버 메모리는 재시작 시 비므로)
- 검증 게이트: 1~2단계 필수 전부 충족(isSubmittable 미러) → 미충족 시 `422 { error: "validation_failed", details: { missing } }`
- 응답: `200 { success: true, applicationStatus: "submitted" }` / `401` / `403` / `409 submit_blocked`
- ⚠️ REFACTORING.md의 `applicationStatus: "applied"` 표기는 실제 enum(`submitted`)과 불일치 — **코드 enum 우선** (상태값 변경 금지 원칙)

### 스모크 테스트 결과 (dev 서버 + curl)

| 케이스 | 기대 | 결과 |
|--------|------|------|
| guest 부분저장 | 401 | ✅ |
| buyer 부분저장(빈 값 포함) | 200 | ✅ |
| step=9 | 400 | ✅ |
| organizer 저장 | 403 | ✅ |
| 미완성 제출 | 422 + missing 목록 | ✅ |
| 완성 제출 | 200 + submitted | ✅ |
| submitted 상태 재제출 | 409 | ✅ |

## 5. 설계 결정

1. **RHF 도입 범위**: `useForm`이 폼 상태·에러의 소스. 단, 스텝 컴포넌트의 `StepProps`(draft/update/errors) 계약은 유지 — 필드 단위 `register` 전환은 Phase 2 "공용 폼 필드 컴포넌트"에서 한 번에 (지금 하면 두 번 손댐).
2. **검증 동기 실행**: `form.trigger()`는 async라 [다음] 클릭 → 에러 표시가 한 틱 늦음(기존 테스트도 이 시점을 동기로 단언). Zod `safeParse` + `setError`로 동기 판정. 입력 시 실시간 에러 해제는 `setValue(shouldValidate)` + zodResolver(현재 단계 스키마).
3. **검증 규칙은 코드가 진실**: `ad-001.page.spec.md`는 Step1 필수를 국문 회사명/담당자명 + email/tel 형식 검사로 기술하지만, 실제 `validateStep()`은 영문 이름/소속 + country 필수·형식 검사 없음. 동등성 유지를 위해 스키마도 코드 기준. email/tel 형식 강화는 `validateStep` 제거 시점에. **spec 문서 업데이트 필요** (미처리).
4. **저장 이중화(과도기)**: 로컬 store(localStorage)가 여전히 복구(재개)의 단일 소스. 서버 POST는 비차단 미러 — 실패해도 이동은 막지 않고 toast만. localStorage 제거는 GET(draft 조회) 라우트가 생겨야 가능 → 잔여 작업.
5. **RSC 경계**: 라우트(서버)가 store를 import하자 `useSyncExternalStore`(클라 전용) 때문에 번들 컴파일 실패 — tsc·vitest는 통과했고 **dev 서버 스모크에서만 발견**. `useBuyerProfile` 훅을 `use-buyer-profile.ts`로 분리해 store를 React 무의존으로 만들었다(훅 사용처는 현재 0곳이라 무파괴).
